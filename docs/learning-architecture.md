# learning-architecture — 학습 카테고리

> 선택 로드 문서. 학습 카테고리 상세를 확인해야 할 때만 읽는다. 공통 라우터 계약·모듈맵은
> `docs/architecture.md`.

## 1. 배경 · 범위 (D-60, D-63, D-64, D-65, D-66, D-67, D-68, D-69, D-72, D-73, D-74)

사용자가 준비한 "영어 학습 웹앱" 로드맵(어르신/어린이 대상, Next.js+Supabase+PG결제 풀스택
기획)을 이 저장소(빌드 없는 정적 SPA, 심리테스트/미니게임 레지스트리)의 세 번째 카테고리로
축소 적용했다. 요금제는 명시적으로 나중으로 미뤘고(사용자 지시), 그 김에 로그인·DB·SRS·결제도
함께 미뤘다 — 전부 영속 저장이 전제인데, 이 앱은 부부 체크의 KV 하나를 유일한 예외로 두고
철저히 무상태다(`CLAUDE.md` "영속 데이터" 항목).

**구조는 3단이다**: 홈 → 학습 목록(도구 카드, `/learning`) → 도구의 목차(챕터 카드, 예
`/learning/basic-conversation`) → 챕터 하나(문장 연습, 예
`/learning/basic-conversation/greeting`). 학습 카테고리 **안에는** 앞으로 다른 공부 도구가
더 들어갈 수 있어 도구 단위는 심리테스트처럼 카탈로그가 맞고, 도구 하나 **안**은 여러
상황(챕터)을 순서대로 밟아나가는 목차형 흐름이다(D-63, 아래 §2 첫 항목에 이 구조를 잡기까지의
시행착오를 적어뒀다).

**v1 범위**: 도구 하나(`js/learning/basic-conversation/` — 기초 영어회화, **7세 이하
대상**(D-69)), 챕터 4개, 총 362문장(기본 122 + 중급 120 + 심화 120, D-74) — `greeting`(인사/기분 표현) ·
`daily-routine`(하루 일과 — 아침+식사+목욕/잠자리+위생 통합) · `family-and-me`(가족·
자기소개+색깔 통합) · `playground`(놀이터에서 — 놀이+날씨+공원 통합). 로드맵 1-2가 준
"동물/음식·학교/놀이터" 같은 단어 카테고리에서, 사용자 지시(D-65)로 "일상대화 위주,
어린이 애니메이션 참고"로 다시 짰다 — 뽀로로·타요·페파피그류가 매번 "아침에 일어나기",
"친구랑 놀기", "밥 먹기", "잠자리"처럼 하루 일과 하나를 에피소드로 삼는 것과 같은 결로,
단어 나열(This is a rabbit)보다 그 상황에서 실제로 오가는 말(Let's play! / Can I have
more?)을 우선했다. 여기서 한 번 더, 사용자 지시(D-66)로 "묶을 수 있는 건 묶어서" 8챕터를
지금의 4챕터로 합쳤다 — 시간순으로 이어지는 상황(아침→식사→목욕/잠자리)이나 소재가
겹치는 상황(가족+자기소개, 놀이+날씨)은 챕터 하나로 묶고, 그 안의 문장 개수를 늘리는
쪽으로 방향을 잡았다(아래 §2 첫 항목). 이어서 사용자 지시(D-67)로 "I like ~"·"This is
my ~"·"I want ~"·"Let's play ~" 같은 문장 틀에 단어만 바꿔 반복하는 패턴 드릴 13문장을
각 챕터에 추가했다(88 → 101문장) — 로드맵 1-2가 애초에 "만능 문장 틀 20개 우선 선정"을
제안했던 것과 같은 방향이다. 그 다음(D-69)엔 사용자가 (1) 실제로 쓰이는 자연스러운
어휘인지 검증, (2) 대상을 7세 이하로 명시, (3) 위생·공원·색깔 등 11문장 추가(101 →
112문장), (4) 한글을 아직 못 읽는 어린이를 위한 한국어 음성 지원을 요청 — 4가지를 한
번에 반영했다(아래 §2). 이어서(D-72) 사용자가 "7세면 실제 대화력이 훨씬 느는데
지금은 입문용 같다, 단계를 나눠서 원어민 7세 수준까지 만들어보자"고 제안 — 각 챕터
끝에 심화 문장 6개씩(총 24개, 112 → 136문장)을 이었다. 마지막으로(D-73) 사용자가
"심화로 바로 넘어가는 게 갑자기 확 어려워지는 것 같다, 기본/중급/심화 30개씩 넣고
챕터를 누르면 단계를 고를 수 있게 하자"고 제안 — 기본을 챕터당 30개 안팎으로 채우고
(112 → 122), 기본과 심화 사이 난이도인 중급 문장을 챕터당 12개씩(총 48개) 새로
넣었다(136 → 194문장). 심화는 이번엔 6개씩 그대로 뒀다 — 30개까지 채우는 건 다음
요청으로 미룬다고 알렸다. 사용자가 바로 "덜 채운 것 마저 채워보자"고 이어서 요청해
(D-74) 중급을 챕터당 30개(총 120개), 심화도 챕터당 30개(총 120개)까지 채웠다(194 →
362문장) — 화면·라우팅·상태 구조는 그대로 두고 데이터만 늘렸다(아래 §2 마지막
항목). 챕터를 누르면 단계 선택 화면이 먼저 뜨고, 단계 하나를 고르면 그 흐름은
로드맵 2-2 그대로: 카드 진입 → 듣기(TTS, 0.75배속 토글) → 말하기(STT) → 결과
(Levenshtein 유사도 기반 3단계 피드백) → 다음 문장. 반복해서 한 단계를 끝내면
완료 화면(처음부터 다시 / 단계 다시 고르기).

## 2. 지금 어떻게 만들었나

- **도구는 레지스트리, 챕터는 데이터(D-63)**: 처음(D-60)엔 챕터 `greeting`을 최상위 도구인
  것처럼 홈 카드에서 바로 등록했다. 사용자가 "목차별로 나열할 수 없다, 하나의 공부 창이
  되어야 한다"고 지적해 레지스트리·목록을 통째로 없앴는데(D-62), 곧이어 "학습 카테고리 안에
  다른 공부 도구도 넣을 거다, 심리테스트 들어가면 종류별로 테스트가 있듯이"라는 요구가
  왔다 — 카탈로그 자체가 필요 없던 게 아니라, **카탈로그가 있어야 할 층이 한 단 아래**였다.
  지금 모양: `registerLearning`/`listLearning`(`js/core/router.js`, `registerTest`와 대칭)이
  **도구**를 등록하고, 도구 하나(`js/learning/<toolId>/`) 안의 `data.js`가 `CHAPTERS` 배열로
  **챕터(목차)** 를 갖는다. `index.js`가 `CHAPTERS.map()`으로 챕터별 화면을 자동 생성해서,
  새 챕터를 추가해도 `index.js`·라우터를 안 고친다(`docs/architecture.md` §5 참고).
- **챕터는 잘게 쪼개지 않고 묶는다(D-66)**: D-65에서 8챕터(각 8~10문장)로 짰더니 목차가
  또 하나의 스크롤 목록이 됐다 — "학습에 하나의 도구로 만들어줘야지, 목차별로 다 나열할
  수 없잖아"(D-62)의 취지가 챕터 레벨에서 다시 반복된 셈이다. 사용자가 "묶을 수 있는 건
  묶어서 한 챕터당 문항수를 늘리고 챕터가 무분별하게 늘어나서 정리 안 되는 상황을
  방지하자"고 정리해줘서, 시간순으로 이어지는 상황(아침→식사→목욕/잠자리)과 소재가
  겹치는 상황(가족+자기소개, 놀이+날씨)을 묶어 4챕터로 줄이고 챕터당 문장 수를 16~30개로
  늘렸다. **앞으로 새 상황이 생기면 새 챕터부터 만들지 않는다** — 기존 챕터 중 시간순으로
  이어지거나 소재가 겹치는 자리가 있는지 먼저 보고, 정말 별개 상황일 때만 새 챕터를
  만든다.
- **폴더**: `js/tests/<id>/`·`js/games/<id>/`와 같은 4파일 구조(`data.js`/`score.js`/
  `screens.js`/`index.js`). `score.js`는 DOM을 모르는 순수 함수(Levenshtein 유사도 + 3단계
  피드백 경계)라 `node --test`(`test/learning.score.test.js`)로 검증되고, 챕터에 무관하게
  도구 하나가 공용으로 쓴다.
- **TTS/STT**: 브라우저 내장 `speechSynthesis`/`SpeechRecognition`만 쓴다. 서버 API·어댑터
  패턴 없음 — 공급자가 하나뿐인데 인터페이스부터 만드는 건 지금 시점에 과설계다(아래 §3-2).
- **한국어 해석도 TTS로 들을 수 있다(D-69)**: 대상이 7세 이하로 좁혀지면서, 한글을 아직
  못 읽는 아이가 많다는 게 실제 문제로 떠올랐다 — 지금까지는 한국어 해석이 화면에
  텍스트로만 있어서, 못 읽는 아이는 부모가 대신 읽어줘야만 뜻을 알 수 있었다. `speak(text,
  rate, lang)`에 `lang` 매개변수를 추가해(기존엔 `"en-US"` 고정) 한국어 해석 옆의 🔊
  버튼(`#learning-listen-ko`)이 `speak(card.ko, 1, "ko-KR")`을 부르게 했다 — 영어 듣기
  버튼과 완전히 같은 메커니즘, 언어만 다르다. 자동 재생은 안 한다 — 브라우저 자동재생
  정책상 사용자 제스처 없이는 안정적으로 안 울리고, 카드를 열 때마다 매번 울리면 반복
  학습 중 오히려 방해가 될 수 있다.
- **문장 데이터 어휘 점검(D-69)**: "실제로 쓰이는 어휘인지" 요청에 맞춰 112문장 전체를
  다시 훑었다 — 전부 원어민이 실제로 쓰는 고빈도 표현이라 교체가 필요한 건 없었다(유일하게
  "Cheers!"가 또래보다는 캐주얼한 어른 말투에 가깝지만, 식사 시작 인사로 흔히 쓰여 오류는
  아니라 남겨뒀다).
- **상태**: `state.learning[chapter.id] ??= { index: 0 }` — 챕터 화면에 처음 들어갈 때
  지연 초기화된다. 몇 번째 문장인지만 있으면 된다. 듣기/말하기 결과(마이크 상태·유사도·피드백)는
  화면 지역 DOM이라 새로고침은 물론 문장 넘김에서도 굳이 state에 넣지 않았다(다음 문장으로
  넘어가면 어차피 사라질 값).
- **화면**: `disc-question`(§ architecture.md D-26)과 같은 in-place 렌더 패턴 —
  `renderChapter(chapter)`가 골격(`back-row` + `#learning-card`)을 한 번만 그리고, 문장이
  바뀔 때마다 `#learning-card`의 innerHTML만 새로 그린다. 목차 화면
  (`renderBasicConversationIntro`)은 `renderPsychList`와 같은 카드 목록 패턴을 재사용한다.
- **에러 처리**: 브라우저가 STT를 지원하지 않거나 인식이 실패하면(`onerror`) 문구로 보여주고
  `console.error`도 남긴다 — 조용히 삼키지 않는다(`CLAUDE.md` 절대 규칙).
- **마스코트 일러스트 없음(D-61 → D-64, 되돌림)**: 처음엔 `js/learning/mascot.js`가 문장
  카드 위에 인라인 SVG 얼굴(표정·소품 조합)을 그렸다. 이미지 생성 도구·파이프라인이 없어서
  코드로 그린 것이었는데, 실제로 렌더된 걸 보니 사용자가 "이모티콘이 별로"라고 판단해
  뺐다(D-64) — 이미지가 정말 필요해지면 그때 실제 이미지 에셋(사람이 그리거나 외부에서
  받은 일러스트)으로 따로 넣는다는 전제다. `mascot.js`와 문장 데이터의 `mood` 필드,
  `test/learning.mascot.test.js`는 전부 삭제했다 — 다시 만들 근거(무엇을 어떻게 그릴지)가
  아직 없는데 코드만 남겨두면 죽은 코드다.
- **건너뛰기(D-61)**: 듣기/말하기를 강제하지 않는다. 이미 아는 문장이면 `#learning-skip`
  버튼으로 마이크 없이 바로 다음 문장으로 넘어갈 수 있다. 마이크로 성공/실패 결과가 나온
  뒤에는 건너뛰기 버튼을 숨긴다(`skipBtn.style.display = "none"`) — 그 시점엔 이미 결과
  카드의 "다음 문장" 버튼이 같은 역할을 하므로, 같은 동작을 하는 버튼 두 개가 같이 보이지
  않게 했다.
- **기본 → 중급 → 심화 3단계 + 단계 선택 화면(D-72, D-73)**: 처음엔(D-72) 문장에
  `level: "advanced"`만 붙일 수 있게 해서(없으면 기초) 같은 챕터를 계속 진행하면
  자연스럽게 심화로 넘어가는 흐름이었다. 사용자가 "심화가 갑자기 확 어려워지는 것
  같다"고 지적해(D-73), `"intermediate"`(중급)를 끼워 넣고 챕터를 누르면 바로 연습으로
  들어가지 않고 **단계를 먼저 고르는 화면**(`renderLevelSelect`)이 뜨도록 바꿨다 — 3단계를
  한 번에 죽 이어 풀기보다, 원하는 단계만 골라 반복할 수 있어야 한다는 판단. 라우팅은
  `/learning/basic-conversation/<chapterId>`가 이제 단계 선택(예전엔 연습 화면이었다)이고,
  실제 연습은 `/learning/basic-conversation/<chapterId>/<level>`로 한 단 더 들어간다 —
  `index.js`가 `CHAPTERS`와 `LEVEL_LABELS`(`{ basic: "기본", intermediate: "중급",
  advanced: "심화" }`, `data.js`에 단일 소스) 둘을 곱해 챕터×단계 화면을 자동 생성한다.
  `renderChapter(chapter, level)`이 `chapter.sentences`를 `level`로 필터링하고, 진행
  상태 키도 `state.learning[chapter.id]`에서 `state.learning[\`${chapter.id}-${level}\`]`로
  바꿔 단계별로 독립적으로 진행된다. 단계 선택 화면과 목차 화면 카드 설명 둘 다 레벨별
  문장 수를 보여주고(`LEVEL_LABELS`를 순회해 자동 생성 — 새 레벨이 추가돼도 이 UI는 안
  고친다), 연습 화면 카드의 "심화" 배지도 `LEVEL_LABELS[level]`로 일반화해 기존 `.cover
  .tag` 클래스를 그대로 재사용했다(새 CSS 없이 됐다). "목차로 돌아가기" 버튼은 이제
  최상위 목차가 아니라 그 챕터의 단계 선택 화면으로 돌아간다("단계 다시 고르기") — 한
  단계를 끝내고 바로 다른 단계로 넘어가기 쉽게.
- **기본/중급/심화 모두 챕터당 30개(D-73 → D-74)**: 사용자는 처음부터 "기본 30·중급
  30·심화 30"을 제안했다. D-73에서는 기본만 30개 안팎으로 채우고(챕터마다 24~26개였던
  걸 각각 4~6개 보태서) 중급은 12개, 심화는 6개로 범위를 좁혀 올렸다 — 세 단계를 한
  번에 30개씩(총 360문장) 채우면 검증 없이 양만 늘어 품질이 떨어질 위험이 있다고
  판단해서였다. 사용자가 바로 "덜 채운 것 마저 채워보자"고 이어서 요청해(D-74) 중급을
  30개(+18×4=72), 심화도 30개(+24×4=96)까지 마저 채웠다 — 총 168문장을 더해 194 →
  362문장(daily-routine만 기본이 32개라 다른 챕터보다 조금 많다). 중급은 D-73에서 정한
  톤(짧은 질문·요청)을 유지했고, 심화는 의견·이유·비교·협상·되묻기 축(D-72)에 화해·공감·
  조건부 추론·협상까지 소재를 넓혀서 같은 패턴이 반복되지 않게 했다.

## 3. 잘라낸 것 — 나중에 어떻게 붙일지

로드맵의 나머지 단계를 "안 만든다"가 아니라 "지금은 안 붙인다, 붙일 때 이렇게"로 기록해둔다.
이 저장소 관례상 되돌리거나 미룬 접근은 여기 적어두고 다시 원점에서 논의하지 않는다.

### 3-1. 로그인 · 영속 데이터 (Supabase Auth 재사용) — D-68에서 붙임
- **지금**: 로그인하면 `state.learning`이 `learning_progress` 테이블(user_id PK, RLS로 본인
  행만 select/insert/update)에 저장된다. `js/core/auth.js`가 관리자 전용 필터를 벗어던지고
  모든 로그인 사용자를 `currentEmail`로 추적하게 되면서(D-68), 로그인 자체는 일반 방문자에게
  열렸다 — `isAdmin()`은 여전히 부부 체크 게이트(D-56)용으로만 남아 있다. `js/learning/cloud.js`가
  로그인 시 서버 값을 로컬과 병합(챕터별로 index가 더 큰 쪽을 남긴다)하고, 문장이 넘어갈 때마다
  업서트한다. 로그아웃했거나 CDN이 막혀 있으면 이 앱의 다른 콘텐츠처럼 세션 한정으로만 동작한다.
- **어떻게 붙였나**: 새 로그인 시스템을 만들지 않고 `js/core/cloud-auth.js`(Supabase Auth,
  카카오·구글 OAuth)를 그대로 재사용했다 — NumPath 마을이 D-55에서 했던 것과 같은 패턴(CDN
  의존을 `cloud-auth-loader.js`의 동적 import 뒤로 숨김)이지만, 코인/마을 같은 보상 체계는
  따라가지 않았다(D-54/55에서 되돌린 건 그 부분뿐이다).

### 3-2. STT/TTS 공급자 교체 (어댑터 패턴)
- **지금**: `speak(text, rate, lang)`/`listen(onResult, onError)`/`supportsSpeech()`/
  `supportsRecognition()`이 `js/learning/speech.js`(도구 폴더 밖, 공용)에 있다 — 원래는
  `basic-conversation/screens.js`에 있었는데, elementary-conversation이 생기면서(D-75)
  두 번째 소비자가 똑같은 로직을 복사하려던 참이라 옮겼다. **다만 이건 "여러 도구가 같은
  구현을 공유"일 뿐, 로드맵 3-2가 말한 "여러 공급자를 갈아끼우는 어댑터"는 아직 아니다** —
  구현체는 여전히 브라우저 내장 `speechSynthesis`/`SpeechRecognition` 하나뿐이다.
- **나중에 붙일 때**: 두 번째 공급자(OpenAI Whisper, ElevenLabs/Azure Speech 등)가 **실제로**
  필요해지는 시점에 이 두 함수를 인터페이스로 놓고 구현체를 갈아끼운다. 공급자가 브라우저
  API 하나뿐인 지금 인터페이스부터 만들면 쓰이지 않는 추상화가 된다 — 함수를 공용 모듈로
  뽑은 것과 "갈아끼울 수 있게 만드는 것"은 다른 일이라는 걸 여기 구분해둔다.

### 3-3. 간격 반복(SRS) · 학습 기록 DB
- **지금(D-75로 절반만 진전)**: elementary-conversation은 "repeat" 문장에서 낮은 점수를
  받거나 produce 문장을 "다시 연습할래요"로 자가평가하면 그 문장 id를
  `state.learning[key].weak`에 남기고, 챕터를 다 풀면 "헷갈렸던 문장만 복습하기"로 그
  목록만 다시 돌 수 있다. **이건 SRS가 아니다** — 같은 세션 안에서 "약한 것 먼저 다시"일
  뿐, 며칠 뒤에 다시 보여주는 시간 간격이 없다. basic-conversation은 이 기능도 아직 없다
  (D-67의 패턴 드릴은 한 세션 안의 반복일 뿐, 이것과도 다른 걸 최적화한다).
- **나중에 붙일 때**: 진짜 SRS(Leitner box·SM-2 등, 마지막 정답 시각 기준으로 "N일 뒤 다시")를
  붙이려면 `weak` 같은 불리언이 아니라 문장별 `lastSeenAt`/`interval` 같은 필드가 필요하고,
  세션이 끝나도 남아 있어야 의미가 있다. D-68로 로그인·`learning_progress` 영속 저장이 이미
  붙었으니(§3-1), "영속 저장 인프라가 없다"는 예전 보류 이유는 사라졌다 — 다음으로 SRS를
  붙일 때는 `learning_progress`의 `progress` JSON에 이 필드들만 추가하면 되고, 익명 사용자는
  지금처럼 세션 한정 `weak` 목록으로 대체된다.

### 3-4. 결제 · 요금제
- **지금**: 없음(사용자 지시로 명시적 보류).
- **나중에 붙일 때**: 이 저장소에 유료 결제가 들어오는 건 처음이라, 붙일 때 포트원/토스페이먼츠
  SDK 연동 방식과 "무엇을 Free/Pro로 가를지"(도구 개수 제한? 챕터 개수 제한? 고품질 음성?)
  부터 다시 정해야 한다 — 지금 만든 v1은 사용자가 이미 정한 무료 정책(로드맵 1-3, 하루 3개
  상황·10~15문장) 중 "무료"쪽만 반영했고 유료 갈림길 자체가 아직 코드에 없다.

### 3-5. 새 도구 · 어르신 모드
(챕터 추가·교체·병합은 더 이상 "잘라낸 것"이 아니다 — 챕터를 늘렸다(D-65) 줄였다(D-66)
하며 이미 이 구조로 여러 번 해봤다. `js/learning/basic-conversation/data.js`의 `CHAPTERS`에
항목만 추가·수정·병합하면 목차 화면·화면 등록이 자동으로 반영된다는 게 실전으로 확인됐다.
새 챕터를 만들 때의 기본값은 이제 "먼저 기존 챕터에 붙일 자리를 본다"다(D-66, 위 §2).)
- **새 도구(다른 과목, 예: 숫자 배우기)**: `js/learning/<newToolId>/`를 통째로 새로 만들고
  `registerLearning`으로 등록한다 — 학습 목록에 카드가 하나 더 생긴다. 심리테스트에 검사
  하나를 추가하는 것과 완전히 같은 절차(`docs/architecture.md` §5).
- **어르신 모드**: 새 카테고리를 또 만들지 않는다 — 학습 목록에 "기초 영어회화(어르신용)"
  같은 별도 도구로 넣거나, 같은 도구 안에 모드 선택을 두는 두 방향이 있는데 아직 결정 안
  했다(실제로 만들 때 판단). UI 원칙 자체는 다르다(대형 버튼·고대비·한글 발음 가이드
  병기) — 챕터 데이터에 `ko` 옆에 `pron`(한글 발음 표기) 필드를 추가하는 정도로 화면 분기
  없이 처리될 것 같다.
- **8~9세용(더 큰 아이) — D-75로 실제로 만들어짐**: D-69에서 대상을 "7세 이하"로 명시하면서
  생겼던 격차를, 여기 적어둔 대로 새 도구(`elementary-conversation`)로 분리해서 메웠다 —
  아래 §3-8 참고. 지금은 저학년(1~2학년) 챕터 4개뿐이라 8~9세보다 조금 더 넓은 학년까지
  잡혀 있고, 중학년·고학년은 아직 없다.

### 3-6. 광고 슬롯
- **지금**: 학습 목록(`learning-list`)에는 다른 목록처럼 배너가 있다. 목차 화면과 챕터
  화면(연습 화면)에는 없다.
- **나중에 붙일 때**: 다른 게임 결과 화면처럼 `adSlotMarkup()`/`adGateMarkup()`을 완료
  화면(`showDone()`)에 붙이면 된다 — 이미 있는 부품이라 새로 만들 게 없다. 파일럿 단계라
  검증 전에는 넣지 않았을 뿐이다.

### 3-7. 다중 턴 대화형 학습
- **지금**: 없음. 문장 하나를 듣고 그대로 따라 말하는 구조뿐이다(질문→대답→되묻기 같은
  주고받기 없음).
- **왜 지금 안 만들었나(D-72)**: 원어민 7세의 진짜 대화력(상황에 맞게 대답을 스스로
  구성하고, 상대 말에 반응해서 되묻는 것)은 "정해진 문장 하나를 얼마나 똑같이 따라
  했는가"로 채점하는 지금 방식과 아예 다른 문제다 — 채점 기준부터(정답이 여러 개일 수
  있다), 화면 흐름부터(문장 하나가 아니라 대화 트리) 다시 설계해야 한다. 그래서 이번엔
  "같은 상황의 문장을 더 어렵게" 정도로 타협했다(위 D-72·D-73의 기본/중급/심화 3단계).
- **나중에 붙일 때**: 사용자 의견 — "대화형 웹앱은 추후에 구축". 지금 도구(`basic-conversation`)를
  고쳐서 넣기보다, 학습 목록에 완전히 새 도구로 추가하는 쪽이 맞아 보인다(§3-5의 "새 도구"
  절차 그대로) — 지금 도구의 "문장 하나 = 카드 하나" 모델과 근본적으로 다른 화면·채점
  구조가 필요해서, 기존 도구를 무리하게 확장하면 두 모델이 한 폴더에 뒤섞인다. 확정 아님,
  실제로 만들 때 화면 구조부터 다시 설계.

### 3-8. 초등 영어회화 (elementary-conversation, D-75, D-76, D-77, D-78)
- **왜 만들었나**: 초등학생 버전 목차(학년 3단계 × 상황별 챕터 4개)를 먼저 제안했더니
  사용자가 "실제로 저 카테고리대로 공부하면 언어 실력향상이 도움이 되게끔 짜여져있다고
  생각해?"라고 되물었다. 정직한 답은 "아니다"였다 — 문법 진행이 없고, 반복(recycling)이
  없고, Levenshtein 유사도 채점이 암기·발음 훈련이지 새 문장을 만드는 능력은 못 봤다.
  "7세 이하는 반복이면 되지만 초등학교부터는 실질적 회화 및 언어 향상이 동반돼야 한다"는
  사용자 판단에 따라 이 세 가지를 보강해서 만들었다.
- **구조**: 학년(`GRADES`) → 챕터(그 학년의 `CHAPTERS`) → 단계(기본/중급/심화,
  basic-conversation과 같은 `LEVEL_LABELS`) → 문장 연습. `index.js`가 `GRADES ×
  chapters × LEVEL_LABELS`를 곱해 화면을 자동 생성한다 — basic-conversation의
  `CHAPTERS × LEVEL_LABELS`(D-73)에 학년 한 겹만 곱한 것. 아직 안 만든 학년(중학년·
  고학년)은 `GRADES` 배열에 아예 없다(이 저장소 관례: 빈 기능을 화면에 먼저 노출하지
  않는다) — 학년 선택 화면엔 실제로 고를 수 있는 학년만 뜬다.
- **문법 진행(scope & sequence)**: 문장마다 `grammar`(그 학년 `grammarPoints`의 id, 예
  `G1` be동사·`G2` 일반동사 현재형·`G3` 조동사 can·`G4` There is/are)를 단다.
  `test/learning.elementary.test.js`가 모든 grammar 태그가 실재하는 포인트를 가리키는지,
  등록만 해두고 쓰이지 않는 죽은 포인트가 없는지 검사한다.
- **반복(recycling)을 테스트로 강제**: "두 번째 챕터부터는 이전 챕터의 grammar를 최소
  1문장 이상 재사용한다"를 자동 검사로 넣었다 — 새 챕터가 새 문법만 도입하고 끝나는 걸
  코드로 막는다. 지금은 학년마다 챕터가 1개뿐이라 이 검사가 아직 트리거되진 않지만,
  챕터를 늘릴 때부터 바로 지켜지게 미리 넣었다.
- **produce 문장**: `type: "produce"`인 문장은 정답을 안 읽어주고 질문만 던진다 —
  `sample`(예시 답안 1개 이상)을 STT 결과 옆에 보여주고 "잘 말했어요/다시 연습할래요"
  자가평가로 넘어간다. 유사도 채점을 안 하는 이유는 정답이 하나가 아니라서다.
- **약한 문장 재노출**: "repeat" 문장에서 낮은 점수를 받거나 produce 문장을 "다시
  연습할래요"로 평가하면 그 문장 id가 `state.learning[key].weak`에 남는다. 챕터 완료
  화면에 "헷갈렸던 문장만 복습하기"가 뜨면, 화면 이동 없이(라우터 `go()`는 화면 id만
  받고 매개변수를 못 넘긴다 — 복습 모드는 공유할 이유가 없는 일시적 상태라 새 주소를
  만들 필요도 없다) `sentences`/`N`/`reviewMode`를 안에서 바꿔 그 목록만 다시 돈다.
  진짜 SRS는 아니다 — §3-3 참고.
- **basic-conversation의 renderChapter를 재사용하지 않은 이유**: 문장 데이터 모양이
  달라졌고(`grammar`, `type`, `sample`), 채점 흐름이 두 갈래(유사도 채점 vs 자가평가)로
  갈라져서, 억지로 하나의 함수에 분기를 늘리면 두 도구의 서로 다른 화면 로직이 한 함수에
  뒤섞인다. 대신 진짜 겹치는 부분(Levenshtein 유사도·TTS/STT 헬퍼)만 `js/learning/
  score.js`·`js/learning/speech.js`로 뽑아 공용화했다.
- **범위**: 처음엔 저학년 챕터 1개(학교 가는 날, 기본 10·중급 6·심화 4, 총 20문장)만
  만들어 메커니즘이 실제로 동작하는 걸 먼저 확인했다 — basic-conversation의 최종 목표
  (단계별 30개)보다 적게 시작한 것도 그래서다. 메커니즘이 확인된 뒤(D-76) 사용자가
  "내용 채워보자"고 요청해(D-77) 같은 틀로 나머지 챕터 3개(교실에서·쉬는 시간·좋아하는
  것)를 채웠다 — 저학년이 4챕터·80문장으로 다 찼다. 문법은 챕터마다 무조건 하나씩 늘리지
  않았다 — `교실에서`가 G5(should)를, `쉬는 시간`이 G6(과거형)를 새로 도입하고,
  `좋아하는 것`은 새 문법 없이 G1~G6를 다른 소재로 다시 섞어 쓰기만 한다("반복이 매
  챕터 새 문법 하나씩"이 아니라는 걸 보여주는 사례로 일부러 이렇게 짰다). 챕터가
  2개 이상이 되면서 `test/learning.elementary.test.js`의 반복 규칙 검사(두 번째 챕터
  부터 이전 챕터 grammar 재사용)가 이번에 처음으로 실제 데이터에 대해 돌아갔다.
  다음 단계였던 중학년도 이어서 채웠다(D-78).
- **중학년(D-78)**: `MIDDLE_GRAMMAR_POINTS`(G7~G11 — 현재형 복습·have to/must·미래형·
  비교급·현재진행형)를 저학년과 별개 배열로 두고, 번호만 안 겹치게 이어 붙였다 — G7이
  저학년 G2(일반동사 현재형)와 개념은 겹치지만 일부러 새 id로 다시 정의했다. 학년
  트랙이 서로 독립적이어야 한다는 게 D-75의 전제라, 중학년이 저학년 grammarPoints를
  그대로 참조하면 두 배열이 실질적으로 하나로 묶여서 나중에 학년 하나만 손보기
  어려워진다. 챕터는 `수업과 과제`(📚)·`친구 관계`(🤝)·`방과 후 생활`(🎨)·
  `우리 동네`(🏘️) 4개, 저학년과 같은 틀(챕터당 20문장)로 만들어 중학년도 4챕터·
  80문장이 됐다 — `우리 동네`는 저학년의 `좋아하는 것`과 같은 이유로 새 문법 없이
  G7~G11만 재사용한다. 저학년(간단한 사실 진술)에서 중학년(의무·미래·비교가 들어간
  문장)으로 이어지는 방향은 목차를 처음 설계할 때 잡아둔 "중학년은 감정·의견 표현이
  늘고 문법이 조금 복잡해짐"과 맞춘 것. 다음 단계: 고학년(의견 나누기·꿈과 진로·요즘
  이슈·여행과 경험, 새 HIGH_GRAMMAR_POINTS부터) — 채워지면 3개 학년이 전부 완성된다.
- **UX 마찰 4건 수정(D-76)**: D-75 직후 사용자가 "구조적으로 공부가 정말 쉽게된다고
  말할수있나?"라고 물어서 정직하게 짚은 네 가지를 그대로 고쳤다.
  1. **학년 선택 화면이 순수 마찰이었다** — 학년이 저학년 하나뿐인데 고를 게 없는
     화면을 거치게 했다. `learning-elementary` 화면에 `GRADES.length === 1`이면 그
     학년의 챕터 목차로 곧장 보내는 `guard`를 달아 해결 — 학년이 늘면 guard가 저절로
     꺼진다. 부작용으로 챕터 목차의 뒤로가기가 다시 튕겨오는 루프가 생겨서, 학년이
     하나일 땐 뒤로가기 대상을 학습 목록으로 바꿨다.
  2. **produce 문장에 시도 전 참고가 없었다** — 백지에서 답해야 해서 얼어붙을 위험이
     있었다. 문장마다 `hint`(문장 시작 조각, 예 "I bring ___.")를 추가해 시도 전에
     보여준다. 예시 답안(`sample`)은 여전히 시도 *후*에만 보여준다 — 미리 보여주면
     그대로 따라 말하는 반복 카드와 다를 게 없어진다.
  3. **문법 태그가 학습자에게 안 보였다** — `grammar`는 원래 저작·반복 검사용 내부
     장치였다. 연습 카드마다 "🔤 오늘의 문법: 조동사 can (능력·허락)" 한 줄을 추가해
     지금 뭘 배우는지 의식하게 했다(메타인지 스캐폴딩).
  4. **복습이 그 순간에만 존재했다** — "헷갈렸던 문장만 복습하기"가 완료 화면에서만
     뜨고 다른 데서 모아볼 방법이 없었다. 마이페이지(D-70)의 학습 집계에 `weak` 총합을
     한 줄 더 보여준다 — 다만 거기서 바로 복습 화면으로 딥링크하진 않는다(그 단계를
     한 번 더 끝까지 풀어야 복습 버튼이 다시 뜬다), 문구도 그렇게 정직하게 적었다.
  네 개 다 화면 흐름을 새로 만들지 않고 기존 장치(guard, 카드 렌더, 마이페이지 집계)에
  얹었다 — `docs/decisions/2028-h2.md` D-76.

## 4. 배포 후 확인 필요

- **실기기 음성 인식**: 헤드리스 브라우저는 마이크·네트워크가 없어 `SpeechRecognition`이
  실제로 동작하는지 확인하지 못했다(가짜 STT를 주입해 판정 로직 자체만 검증). iOS
  Safari·Android Chrome에서 마이크 권한 승인 흐름, 인식 정확도, 첫 시도 지연을 확인 필요.
- **`speechSynthesis` 실기기 음질·속도**: 0.75배속 재생이 실제 목소리로 자연스럽게 들리는지
  기기별 확인 필요(브라우저 내장 TTS라 기기·OS마다 목소리가 다르다).
- **초등 영어회화 produce 문장 실기기 확인(D-75)**: 자유 발화라 STT 인식 실패율이 정해진
  문장을 따라 말할 때보다 높을 수 있다 — 아이가 문법에 안 맞거나 짧게 답해도 인식 자체는
  되는지, "다시 연습할래요" 자가평가로 넘어가는 흐름이 아이 입장에서 자연스러운지 실기기
  확인 필요(헤드리스 샌드박스는 가짜 STT로 로직만 확인했다).
