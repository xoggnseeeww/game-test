# learning-architecture — 학습(외국어 연습) 카테고리

> 선택 로드 문서. 학습 카테고리 상세를 확인해야 할 때만 읽는다. 공통 라우터 계약·모듈맵은
> `docs/architecture.md`.

## 1. 배경 · 범위 (D-60)

사용자가 준비한 "영어 학습 웹앱" 로드맵(어르신/어린이 대상, Next.js+Supabase+PG결제 풀스택
기획)을 이 저장소(빌드 없는 정적 SPA, 심리테스트/미니게임 레지스트리)의 세 번째 카테고리로
축소 적용했다. 요금제는 명시적으로 나중으로 미뤘고(사용자 지시), 그 김에 로그인·DB·SRS·결제도
함께 미뤘다 — 전부 영속 저장이 전제인데, 이 앱은 부부 체크의 KV 하나를 유일한 예외로 두고
철저히 무상태다(`CLAUDE.md` "영속 데이터" 항목).

**v1 범위**: 어린이 모드 파일럿 하나(`js/learning/greeting/` — 인사/기분 표현, 문장
`SENTENCES.length`개). 흐름은 로드맵 2-2 그대로: 카드 진입 → 듣기(TTS, 0.75배속 토글) →
말하기(STT) → 결과(Levenshtein 유사도 기반 3단계 피드백) → 다음 문장. 반복해서 상황 하나를
끝내면 완료 화면.

## 2. 지금 어떻게 만들었나

- **레지스트리**: `registerGame`/`listGames`를 그대로 복사한 `registerLearning`/`listLearning`
  (`js/core/router.js`). 학습 콘텐츠는 게임과 마찬가지로 "테스트 점수에 반영되지 않는 독립
  콘텐츠"라 모양이 같다 — 다르게 다룰 이유가 생기면 그때 갈라진다.
- **폴더**: `js/tests/<id>/`·`js/games/<id>/`와 같은 4파일 구조(`data.js`/`score.js`/
  `screens.js`/`index.js`). `score.js`는 DOM을 모르는 순수 함수(Levenshtein 유사도 + 3단계
  피드백 경계)라 `node --test`(`test/learning.score.test.js`)로 검증된다.
- **TTS/STT**: 브라우저 내장 `speechSynthesis`/`SpeechRecognition`만 쓴다. 서버 API·어댑터
  패턴 없음 — 공급자가 하나뿐인데 인터페이스부터 만드는 건 지금 시점에 과설계다(아래 §3-2).
- **상태**: `state.learning.greeting = { index: 0 }` — 몇 번째 문장인지만 있으면 된다.
  듣기/말하기 결과(마이크 상태·유사도·피드백)는 화면 지역 DOM이라 새로고침은 물론 문장
  넘김에서도 굳이 state에 넣지 않았다(다음 문장으로 넘어가면 어차피 사라질 값).
- **화면**: `disc-question`(§ architecture.md D-26)과 같은 in-place 렌더 패턴 —
  `renderLearningGreeting()`이 골격(`back-row` + `#learning-card`)을 한 번만 그리고, 문장이
  바뀔 때마다 `#learning-card`의 innerHTML만 새로 그린다.
- **에러 처리**: 브라우저가 STT를 지원하지 않거나 인식이 실패하면(`onerror`) 문구로 보여주고
  `console.error`도 남긴다 — 조용히 삼키지 않는다(`CLAUDE.md` 절대 규칙).

## 3. 잘라낸 것 — 나중에 어떻게 붙일지

로드맵의 나머지 단계를 "안 만든다"가 아니라 "지금은 안 붙인다, 붙일 때 이렇게"로 기록해둔다.
이 저장소 관례상 되돌리거나 미룬 접근은 여기 적어두고 다시 원점에서 논의하지 않는다.

### 3-1. 로그인 · 영속 데이터 (Supabase Auth 재사용)
- **지금**: 없음. 새로고침하면 진행 상황이 사라진다(이 앱의 다른 모든 콘텐츠와 동일).
- **나중에 붙일 때**: 이미 관리자 로그인이 `js/core/cloud-auth.js`(Supabase Auth, 카카오·구글
  OAuth)를 갖고 있다 — 새 로그인 시스템을 만들 필요 없이 이 클라이언트를 재사용한다.
  `state.learning.<id>`를 로그인 성공 시 Supabase 테이블에 업서트하는 함수 하나만 추가하면
  된다(NumPath 마을이 D-55에서 했던 방식과 동일한 패턴 — 단, NumPath 마을 자체는 메리트
  부족으로 되돌렸으니(D-54/55) "이 패턴을 재사용하되 코인/마을 같은 보상 체계까지 따라가진
  않는다"는 전제를 붙인다).

### 3-2. STT/TTS 공급자 교체 (어댑터 패턴)
- **지금**: `speechSynthesis`/`SpeechRecognition` 호출이 `screens.js`에 직접 있다.
- **나중에 붙일 때**: 두 번째 공급자(OpenAI Whisper, ElevenLabs/Azure Speech 등)가 **실제로**
  필요해지는 시점에 `speak(text, rate)`/`listen(onResult, onError)` 두 함수를 인터페이스로
  놓고 구현체를 갈아끼운다. 공급자가 브라우저 API 하나뿐인 지금 만들면 쓰이지 않는 추상화가
  된다 — 로드맵 3-2의 "확장형 어댑터 패턴"을 선반영하지 않은 이유.

### 3-3. 간격 반복(SRS) · 학습 기록 DB
- **지금**: 틀린 문장을 따로 추적하지 않는다. 세션 내에서 몇 번이고 다시 들을 수 있을 뿐이다.
- **나중에 붙일 때**: `Learning_Logs`(로드맵 5-2)를 로그인 이후에나 의미 있는 기능으로 미룬다 —
  익명 사용자에게 SRS를 붙이려면 결국 기기 로컬(`localStorage`)에 "복습 필요" 문장 id 목록을
  두는 절충안이 되는데, 이건 부부 체크의 KV 예외처럼 "영속 데이터 없음" 원칙에 새 예외를
  만드는 결정이라 가볍게 넣지 않는다. 로그인이 붙은 뒤 서버 쪽에 붙이는 게 순서상 맞다.

### 3-4. 결제 · 요금제
- **지금**: 없음(사용자 지시로 명시적 보류).
- **나중에 붙일 때**: 이 저장소에 유료 결제가 들어오는 건 처음이라, 붙일 때 포트원/토스페이먼츠
  SDK 연동 방식과 "무엇을 Free/Pro로 가를지"(문장 개수 제한? 상황 카테고리 개수 제한? 고품질
  음성?)부터 다시 정해야 한다 — 지금 만든 v1은 사용자가 이미 정한 무료 정책(로드맵 1-3, 하루
  3개 상황·10~15문장) 중 "무료"쪽만 반영했고 유료 갈림길 자체가 아직 코드에 없다.

### 3-5. 어르신 모드
- **지금**: 어린이 모드만.
- **나중에 붙일 때**: 같은 레지스트리·폴더 구조로 `js/learning/<어르신 상황 id>/`를 새로
  만들면 된다(예: 공항/출입국, 병원/약국). UI 원칙이 다르다(대형 버튼·고대비·한글 발음
  가이드 병기) — 카드 데이터에 `ko` 옆에 `pron`(한글 발음 표기) 필드를 추가하고 화면 쪽에서
  분기 없이 그 필드가 있으면 보여주는 정도로 충분할 것 같다(확정 아님, 실제로 만들 때 판단).

### 3-6. 광고 슬롯
- **지금**: 목록 화면(`learning-list`)에는 다른 목록처럼 배너가 있지만, 재생 화면
  (`learning-greeting`)엔 없다.
- **나중에 붙일 때**: 다른 게임 결과 화면처럼 `adSlotMarkup()`/`adGateMarkup()`을 완료
  화면(`showDone()`)에 붙이면 된다 — 이미 있는 부품이라 새로 만들 게 없다. 파일럿 단계라
  검증 전에는 넣지 않았을 뿐이다.

## 4. 배포 후 확인 필요

- **실기기 음성 인식**: 헤드리스 브라우저는 마이크·네트워크가 없어 `SpeechRecognition`이
  실제로 동작하는지 확인하지 못했다(가짜 STT를 주입해 판정 로직 자체만 검증). iOS
  Safari·Android Chrome에서 마이크 권한 승인 흐름, 인식 정확도, 첫 시도 지연을 확인 필요.
- **`speechSynthesis` 실기기 음질·속도**: 0.75배속 재생이 실제 목소리로 자연스럽게 들리는지
  기기별 확인 필요(브라우저 내장 TTS라 기기·OS마다 목소리가 다르다).
