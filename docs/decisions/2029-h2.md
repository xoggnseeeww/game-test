### D-98. 9급 공무원 영단어(civil-vocab) 신설 — 어원 중심 어휘 도구, 데이터는 DAY 단위 동적 로드
- **배경**: 사용자 요청 — "학습에 9급 공무원 대상 영어 어휘 공부 도구. 연상암기법과 효율적인
  반복 암기법 도입. 로그인해서 쓰면 계정마다 공부한 걸 확인할 수 있는 시스템. **어휘 8000개
  목표.** 계획부터 잡아봐."
- **먼저 계획을 냈고, 사용자가 세 갈래를 확정했다**: ①복습은 분리(도구를 가로지르는 "오늘
  복습"에 어휘를 섞지 않는다) ②연상은 **어원 우선** ③**200단어 먼저**(M1) 만들고 콘텐츠는
  뒤에 붙인다.
- **핵심 판단: 기존 학습 도구 방식을 그대로 쓰면 8000단어에서 세 군데가 깨진다.**
  1. **데이터 로딩** — 기존 도구는 `data.js`를 `index.js`가 정적 import해서 부팅에 전부
     실린다. 8000단어면 첫 화면에서 수 MB를 받는다. → `manifest.js`(스테이지·DAY
     메타데이터)만 정적 import하고 단어 본문은 `words/day-NNN.js`(50단어씩)를 **동적
     import**로 받는다. 헤드리스로 확인: 홈·학습 목록·도구 인트로까지는 단어 파일을
     **한 번도 요청하지 않고**, DAY에 들어간 순간 그 DAY 하나만 받는다.
  2. **진행률 저장** — `state.learning`은 통째로 한 행에 업서트된다(`cloud.js`). 8000단어
     진행을 여기 섞으면 카드 한 장 넘길 때마다 수백 KB를 올린다. → `state.vocab`을 새
     최상위 키로 분리했다. 계정별 저장은 **단어별 행을 갖는 별도 테이블**로 붙일 예정
     (`docs/vocab-architecture.md` §4) — 그때 `CLAUDE.md` "영속 데이터" 항목과 `/privacy`도
     같은 커밋에 갱신한다.
  3. **간격 반복** — `srs.js`의 Leitner 스케줄은 마지막 칸을 넘기면 목록에서 **지운다(졸업)**.
     "틀린 문장 몇 개"에는 맞지만, 8000단어 장기 보존에서는 한 번 맞힌 단어가 영구히 사라지는
     규칙이 된다. → 재사용하지 않고 별도 스케줄러(SM-2 변형)를 다음 단계에 만든다. **지금
     껍데기를 미리 만들어두지 않았다** — 쓰이지 않는 추상화는 §3-2에서 이미 안 만들기로 한 것과
     같은 판단.
- **연상암기법을 "단어마다 하나"가 아니라 어원 사전으로 짠 이유**: 단어마다 연상을 지으면
  8000개를 각각 저작하고 각각 외워야 한다. 어근은 되풀이된다(`tain` 하나로 attain·maintain·
  obtain·pertain·retain···) — 사전(`roots.js`, 지금 156항목) + 단어별 한 줄 힌트로 나누니
  200단어를 쓰는 데 어근 156개가 만들어졌고, 그 뒤 단어들은 대부분 **이미 있는 어근을 다시
  쓴다**(저작량과 학습량이 같이 준다). 어원이 뚜렷하지 않은 단어(`boost`)는 억지로 붙이지 않고
  `sound`(소리연상)를 쓴다 — D-94의 "억지 데이터는 신호가 없는 것보다 나쁘다". 다만 **둘 다
  없는 단어는 테스트가 막는다**(그러면 "그냥 외워라"가 되어 이 도구의 이유가 없다).
- **복습을 분리한 근거**(사용자 확정): D-92의 "오늘 복습"은 문장 카드 UI이고 하루 수십~수백
  개가 나오는 단어와 섞이면 그 화면이 단어로 덮인다. 그래서 이 도구는 `resolveReview`를
  **일부러 두지 않는다** — 빠뜨린 게 아니라 결정이라는 걸 `index.js` 주석과 이 항목에 적어둔다.
  대신 진입로가 파편화되지 않도록, 어휘 복습 화면이 생길 때 학습 목록·마이페이지에 "단어 N개"
  줄을 따로 노출한다.
- **8000이라는 목표에 대해 사실 하나를 알렸다**: 9급 실전에 실제로 필요한 어휘는 통상
  3000~4500 수준으로 본다. 목표를 줄이지 않는 대신 `freq`(빈출 등급)를 데이터의 단일 소스로
  두고 **앞쪽 2000단어가 시험의 대부분을 덮도록** 배치해서, 중간에 멈춰도 손해가 없게 했다.
- **범위(M1)**: 단어 200개(DAY 4개 × 50) · 어원 156항목 · 화면 2종(DAY 목록 / DAY 세션:
  단어 카드 → 4지선다 확인 문제 → 결과). 4지선다의 **오답 보기는 같은 DAY의 다른 단어 뜻**에서
  자동 생성한다(D-95에서 쓴 방식 — 보기를 저작하지 않으므로 단어가 늘면 문제도 는다).
- **검증**: `npm test` **194/194**(`test/learning.vocab.test.js` 14개 신설 — 매니페스트와 실제
  파일 개수 대조 · 단어 id가 자기 DAY를 가리키는지 · 표제어 중복 · 필수 필드 · 어근 실재 ·
  죽은 어근 · 예문에 표제어 포함 · 모든 DAY가 보기 4개를 만들 수 있는지 · 시드 재현성 ·
  로더의 경로 검증 · **단어 파일 정적 import 금지**). **버그를 일부러 되살려 빨간불 확인**:
  ①session.js에 단어 파일 정적 import 추가 ②매니페스트 count를 49로 조작 ③안 쓰는 어근 추가
  ④없는 어근 참조 — 네 경우 모두 빨간불, 복구 후 194/194.
  헤드리스 브라우저로 30항목 확인(부팅~인트로에서 단어 파일 미요청 · DAY 진입 시에만 동적
  로드 · 다른 DAY는 안 받음 · 어근 칩/힌트/예문 렌더 · 카드 앞뒤 이동 · 50문제 완주 · 정답/오답
  표시 · 결과 정답률 · 틀린 단어만 다시 보기 · 주소 직접 접속 · **로딩 중 이탈해도 다른 화면
  위에 카드를 안 그림**). 기존 회귀 스위트(`scripts/verify.cjs`)도 전부 통과.
- **다음 단계(확정 아님)**: SRS 스케줄러 + `/today` 큐(M2) → 계정별 저장 테이블(M3) →
  통계·스트릭(M4) → 콘텐츠 800 → 2000 → 4000 → 8000(M5). 코드는 M1~M4에서 거의 끝나고
  나머지는 데이터라, 확장 절차(파일 추가 + 매니페스트 한 줄)를 `CLAUDE.md` 동기화 매트릭스에
  적어뒀다.
- **후속(같은 날, 오류 검토)**: 사용자 요청으로 다시 훑어 6건을 고쳤다. **어원 오류 3건이
  가장 나빴다** — 이 도구는 어원을 근거로 외우게 하므로 어원이 틀리면 도구의 신뢰가 통째로
  깨진다: `attain`(칩은 tain=잡다인데 힌트는 "닿다" — 실제로는 tangere 계통이라 tain과 다른
  뿌리 → `tang` 신설), `abandon`(ab-가 아니라 banish와 같은 bann), `acknowledge`(ac-는 라틴
  ad-가 아니다 → `know`), `diminish`(di-는 de-). **검사 하나를 추가해 절반은 기계가 잡게
  했다** — "힌트가 자기 어근 표기를 실제로 담고 있는가"(뜻의 어긋남까지는 못 잡지만, 표기
  누락은 잡는다). 동작 오류 2건: 부분 회차(틀린 단어만 다시 보기)가 DAY 전체의 최고 정답률을
  덮어쓰던 것, 카드를 다 본 뒤 배지가 "51번째"로 뜨던 것. 예문 1건(incline).
- **효율성 검토는 코드로 옮기지 않았다**: 지금 구조의 약점(카드 직후 같은 세트를 바로 묻는
  지연 0 인출 · 어원과 정답을 동시에 노출해 생기는 유창성 착각 · 세션이 끝나면 재노출이
  없음 · 단어별 이력이 회차마다 초기화됨 · 재인(4지선다)만 훈련)은 **무엇을 먼저 붙일지가
  설계 결정**이라 사용자에게 선택지로 넘겼다. 특히 "예문 빈칸 모드"는 예문에 표제어가 반드시
  들어 있다는 걸 테스트가 이미 보장하므로 **콘텐츠를 새로 만들지 않고** 산출 연습을 추가할 수
  있다는 점을 함께 보고했다.

### D-99. 어휘 학습을 "읽고 지나가기"에서 "떠올려 쓰기"로 — 지연 노출 · 빈칸 채우기 · 간격 반복
- **배경**: 사용자가 D-98 직후 "오류 검토 및 공부의 효율성 검토"를 요청했다. 오류는 6건을
  고쳤고(위 항목 후속), **효율성 쪽 진단이 이 항목이다**: 그때 만든 M1은 카드 50장을 훑고
  곧바로 같은 50개를 4지선다로 묻는 구조라, ①인출 지연이 0이고 ②정답·어원이 카드에 항상
  같이 떠 있어 읽고 나면 아는 것처럼 느끼며(유창성 착각) ③세션이 끝나면 다시 만날 장치가
  없고 ④단어별 이력이 회차마다 초기화되고 ⑤재인(고르기)만 훈련했다. 사용자가 우선순위를
  "①②를 먼저, 그다음 ③"으로 정해줘서 그 순서로 만들었다.
- **① 뜻·어원 지연 노출**: 카드 앞면은 **단어와 품사만**. "뜻 확인하기"를 눌러야 뜻·어근 칩·
  힌트·예문이 열리고, 거기서 😅 헷갈려요 / 👍 알겠어요로 스스로 평가한다. **강제하지 않는다** —
  토글로 끄면 예전처럼 바로 다 보인다(D-61·D-93과 같은 판단: 처음 보는 단어는 그냥 읽는 게
  맞을 때도 있고, 그 시점은 학습자만 안다). 설정은 `state.vocab.prefs.recall`로 세션 한정
  표시 설정이라 진행률과 섞지 않는다.
- **② 빈칸 채우기(산출)**: 4지선다는 보기 중에 답이 있어 떠올리지 않아도 맞힐 수 있다.
  **예문에서 표제어를 지워** 직접 쓰게 하는 단계를 붙였다 — 콘텐츠를 새로 만들지 않았다.
  D-98이 넣어둔 검사("예문에 표제어가 굴절형 포함 들어 있다")가 이 방식의 전제였고, 실제로
  200단어 전부에서 빈칸 문제가 만들어지는 걸 테스트가 확인한다. 채점은 예문 형태와 표제어
  형태를 둘 다 받아준다(철자 연습이지 굴절 시험이 아니다), 힌트는 첫 글자와 길이만.
  같은 단어가 두 번 나오는 예문은 두 자리 모두 지운다 — 지금 데이터엔 그런 예문이 없어서
  전역 치환을 없애도 초록불이었다. **합성 데이터로 규칙 자체를 잠갔다**(8000개로 늘면 반드시 생긴다).
- **③ 간격 반복**: `js/learning/civil-vocab/srs.js`(SM-2 변형). 처음 두 번은 고정(1일 → 3일),
  그 뒤 `간격 × ease`(1 → 3 → 8 → 20 → 50 → 125일), 틀리면 간격 0 + ease −0.2 + lapses++.
  **졸업(삭제)이 없다** — 문장용 `js/learning/srs.js`를 재사용하지 않은 이유가 정확히 이것이다
  (그쪽은 마지막 칸을 넘기면 목록에서 지운다. 8000단어에서는 "한 번 맞히면 영구히 사라진다"가 된다).
  `/learning/civil-vocab/today`가 그 일정을 돈다: 복습 + 신규(하루 상한 기본 20)를 섞고,
  인출 강도는 `reps >= 2`부터 고르기 → 빈칸으로 올라간다.
- **큐가 안 끝나는 문제를 미리 막았다**: 틀린 항목을 같은 세션에 무한히 되돌리면 "남은 개수"가
  줄지 않는 화면이 된다(헤드리스로 전부 오답을 내봤더니 59개 큐가 182번 상호작용이 됐다).
  **한 세션에 두 번까지만** 되돌리도록 상한을 뒀다(110번으로 줄었다) — 오늘 못 외운 단어는
  어차피 내일 일정에 이미 올라 있다. 진행바 분모도 남은 양에 맞춰 매번 다시 잰다.
- **경계 하나를 지켰다**: `state.vocab.newPerDay`의 기본값을 `core/state.js`에 넣으려다
  되돌렸다 — core가 `civil-vocab/manifest.js`를 import하면 "core는 학습 콘텐츠를 모른다"는
  의존 방향이 뒤집힌다. 도구 화면이 처음 열릴 때 지연 초기화한다
  (`state.learning[chapter.id] ??= {...}`와 같은 방식).
- **검증**: `npm test` **207/207**(간격 곡선·실패 시 되돌림·ease 하한·hard < good·깨진 엔트리
  방어·밀린 순서·빈칸 생성/채점/중복 치환·큐 섞기·인출 강도 승급 등 11개 추가). 스케줄러의
  성장 규칙과 전역 치환을 각각 망가뜨려 빨간불 확인. 헤드리스 27항목(앞면에 뜻이 안 보임 →
  확인 후 보임 → 토글로 끄면 즉시 공개 · 빈칸 입력/엔터 제출/오답 피드백 · 오늘 큐가 복습과
  신규를 섞어 돌고 헷갈린 단어가 같은 세션에 문제로 다시 나옴 · 재노출 상한 · 완료 화면).
  기존 `scripts/verify.cjs`도 통과.
- **남은 한계(다음이 M3)**: 일정이 아직 **세션 메모리**라 새로고침하면 날아간다. SRS는 날짜를
  두고 다시 만나야 의미가 있으므로, 계정별 저장(`vocab_progress` 테이블)이 붙어야 이 기능이
  실제로 작동한다. `state.vocab.cards[wordId]`의 모양을 그대로 한 행으로 옮기도록 맞춰뒀다.
  localStorage로 임시 저장하는 길은 **일부러 안 갔다** — 영속 데이터가 늘면 개인정보처리방침·
  `CLAUDE.md` "영속 데이터" 항목을 함께 고쳐야 하고, 그건 계정 저장과 한 번에 하는 게 맞다.

### D-100. 어휘 일정을 계정에 저장 — 단어별 행 테이블(vocab_progress) · 그 과정에서 발견한 GRANT 누락
- **배경**: D-99로 간격 반복을 붙였지만 일정이 **세션 메모리**라 새로고침하면 날아갔다. SRS는
  날짜를 두고 다시 만나야 의미가 있으므로, 계정별 저장이 있어야 그 기능이 비로소 작동한다.
- **저장 모양을 학습 진행률과 다르게 잡았다**: `learning_progress`는 `user_id` 한 행에
  `progress` JSONB를 통째로 넣고 바뀔 때마다 전체를 업서트한다. 8000단어를 여기 얹으면
  ①카드 한 장마다 수백 KB를 올리고 ②두 기기에서 공부하면 나중에 올린 쪽이 상대의 진행을
  **통째로 덮어쓴다**. 그래서 `(user_id, word_id)`를 PK로 하는 **행 단위** 테이블을 새로 만들었다 —
  응답 하나가 100바이트 남짓이고, 충돌 범위가 "같은 단어를 같은 시각에 공부한 경우"로 좁아진다.
- **병합은 "마지막 응답이 이긴다"**: 그러려면 엔트리에 응답 시각이 있어야 해서 `srs.js`의
  엔트리에 `at`을 추가했다(일정 계산엔 안 쓰이고 병합에만 쓰인다 — 서버의 `updated_at`과 같은 값).
  시각이 같으면 더 많이 진행된 쪽. 멱등이라 재로그인·다른 탭에서 여러 번 돌아도 결과가 같다
  (`mergeVocabCards`, 순수 함수라 `node --test` 대상 — 병합이 조용히 틀리면 화면엔 아무 표시가
  없고 공부한 일정만 사라진다).
- **요청을 모아서 보낸다**: 카드마다 요청을 보내면 세션 하나에 수백 번이 된다. 10개 또는 4초로
  묶어 업서트하고, **화면 이탈(`onLeave`)과 탭 숨김(`visibilitychange`)에 flush**한다.
  로그인 시에는 서버 행을 **페이지를 넘겨 전부** 받는다(Supabase 기본 1000행 상한) — 일부만
  받으면 "이미 만난 단어"를 몰라서 같은 단어가 다시 새 단어로 나온다.
- **여기서 진짜 문제를 하나 발견했다 — `learning_progress`가 배포된 뒤 한 번도 저장된 적이 없었다.**
  새 테이블의 RLS를 확인하다가 `anon`/`authenticated` 역할에 **테이블 GRANT가 없다**는 걸 봤고,
  대조해 보니 `numpath_village`에는 있고 `learning_progress`에는 없었다(그래서 행 0). Supabase는
  접근 제어가 두 겹(테이블 GRANT → RLS 정책)인데, **대시보드로 만들면 GRANT가 자동으로 붙고
  SQL로 만들면 안 붙는다.** 정책에 닿기도 전에 `permission denied`(42501)로 막히고, 화면에는
  아무 표시가 없어 조용히 실패한다. 보안 어드바이저도 이 경우를 안 잡아준다(RLS는 켜져 있으니까).
  → 두 테이블 모두에 `grant select, insert, update ... to authenticated`를 적용했다. D-68의
  학습 진행률 동기화도 이제야 실제로 동작한다. 패턴은 `docs/ERRORS.md` **E-16**으로 남겼다.
- **개인정보처리방침을 같은 커밋에 고쳤다**: 영속 데이터가 하나 더 생겼으므로 필수다(이 저장소
  규칙 — 실제로 저장하는 것만 적되, 생기면 반드시 적는다). 저장하는 것은 단어 번호와 일정 숫자
  뿐이고 **입력한 답·오답 내용은 저장하지 않는다**는 것도 명시했다. 나아가 "서버에 저장하는데
  방침에 없는" 상태를 테스트로 막았다 — 방침이 낡는 건 화면에 아무 표시가 안 나는 종류의 실수다.
- **검증**: `npm test` **212/212**(병합 규칙·행↔엔트리 왕복·응답 시각 기록·방침 정합성 5개 추가),
  병합 규칙과 `at` 기록을 각각 망가뜨려 빨간불 확인. 헤드리스로 **비로그인 경로**가 그대로
  도는 것 확인(CDN이 막힌 샌드박스라 `loadCloudAuth()`가 null을 주고 저장만 조용히 빠진다 —
  D-56 이후 이 앱이 계속 지켜온 성질). DB 쪽은 `authenticated` 권한과 RLS를 SQL로 직접 확인했다
  (JWT 없는 authenticated로는 0행이 보이고 쓰기도 막힌다, 테이블 행 0 유지).
- **아직 못 한 것**: 실제 Google 로그인 상태에서의 왕복은 샌드박스에서 CDN이 막혀 확인할 수
  없다 — **배포 후 실기기에서 한 번 확인해야 한다**(로그인 → 단어 몇 개 → 새로고침 → 진행 유지).
