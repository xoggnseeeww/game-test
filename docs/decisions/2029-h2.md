### D-98. 9급 공무원 영단어(civil-vocab) 신설 — 어원 중심 어휘 도구, 데이터는 DAY 단위 동적 로드
- **배경**: 사용자 요청 — "학습에 9급 공무원 대상 영어 어휘 공부 도구. 연상암기법과 효율적인
  반복 암기법 도입. 로그인해서 쓰면 계정마다 공부한 걸 확인할 수 있는 시스템. **어휘 8000개
  목표.** 계획부터 잡아봐."
- **먼저 계획을 냈고, 사용자가 세 갈래를 확정했다**: ①복습은 분리(도구를 가로지르는 "오늘
  복습"에 어휘를 섞지 않는다) ②연상은 **어원 우선** ③**200단어 먼저**(M1) 만들고 콘텐츠는
  뒤에 붙인다.
- **핵심 판단: 기존 학습 도구 방식을 그대로 쓰면 8000단어에서 세 군데가 깨진다.**
  1. **데이터 로딩** — 기존 도구는 `data.js`를 `index.js`가 정적 import해서 부팅에 전부
     실린다. 8000단어면 첫 화면에서 수 MB를 받는다. → `manifest.js`(스테이지·DAY
     메타데이터)만 정적 import하고 단어 본문은 `words/day-NNN.js`(50단어씩)를 **동적
     import**로 받는다. 헤드리스로 확인: 홈·학습 목록·도구 인트로까지는 단어 파일을
     **한 번도 요청하지 않고**, DAY에 들어간 순간 그 DAY 하나만 받는다.
  2. **진행률 저장** — `state.learning`은 통째로 한 행에 업서트된다(`cloud.js`). 8000단어
     진행을 여기 섞으면 카드 한 장 넘길 때마다 수백 KB를 올린다. → `state.vocab`을 새
     최상위 키로 분리했다. 계정별 저장은 **단어별 행을 갖는 별도 테이블**로 붙일 예정
     (`docs/vocab-architecture.md` §4) — 그때 `CLAUDE.md` "영속 데이터" 항목과 `/privacy`도
     같은 커밋에 갱신한다.
  3. **간격 반복** — `srs.js`의 Leitner 스케줄은 마지막 칸을 넘기면 목록에서 **지운다(졸업)**.
     "틀린 문장 몇 개"에는 맞지만, 8000단어 장기 보존에서는 한 번 맞힌 단어가 영구히 사라지는
     규칙이 된다. → 재사용하지 않고 별도 스케줄러(SM-2 변형)를 다음 단계에 만든다. **지금
     껍데기를 미리 만들어두지 않았다** — 쓰이지 않는 추상화는 §3-2에서 이미 안 만들기로 한 것과
     같은 판단.
- **연상암기법을 "단어마다 하나"가 아니라 어원 사전으로 짠 이유**: 단어마다 연상을 지으면
  8000개를 각각 저작하고 각각 외워야 한다. 어근은 되풀이된다(`tain` 하나로 attain·maintain·
  obtain·pertain·retain···) — 사전(`roots.js`, 지금 156항목) + 단어별 한 줄 힌트로 나누니
  200단어를 쓰는 데 어근 156개가 만들어졌고, 그 뒤 단어들은 대부분 **이미 있는 어근을 다시
  쓴다**(저작량과 학습량이 같이 준다). 어원이 뚜렷하지 않은 단어(`boost`)는 억지로 붙이지 않고
  `sound`(소리연상)를 쓴다 — D-94의 "억지 데이터는 신호가 없는 것보다 나쁘다". 다만 **둘 다
  없는 단어는 테스트가 막는다**(그러면 "그냥 외워라"가 되어 이 도구의 이유가 없다).
- **복습을 분리한 근거**(사용자 확정): D-92의 "오늘 복습"은 문장 카드 UI이고 하루 수십~수백
  개가 나오는 단어와 섞이면 그 화면이 단어로 덮인다. 그래서 이 도구는 `resolveReview`를
  **일부러 두지 않는다** — 빠뜨린 게 아니라 결정이라는 걸 `index.js` 주석과 이 항목에 적어둔다.
  대신 진입로가 파편화되지 않도록, 어휘 복습 화면이 생길 때 학습 목록·마이페이지에 "단어 N개"
  줄을 따로 노출한다.
- **8000이라는 목표에 대해 사실 하나를 알렸다**: 9급 실전에 실제로 필요한 어휘는 통상
  3000~4500 수준으로 본다. 목표를 줄이지 않는 대신 `freq`(빈출 등급)를 데이터의 단일 소스로
  두고 **앞쪽 2000단어가 시험의 대부분을 덮도록** 배치해서, 중간에 멈춰도 손해가 없게 했다.
- **범위(M1)**: 단어 200개(DAY 4개 × 50) · 어원 156항목 · 화면 2종(DAY 목록 / DAY 세션:
  단어 카드 → 4지선다 확인 문제 → 결과). 4지선다의 **오답 보기는 같은 DAY의 다른 단어 뜻**에서
  자동 생성한다(D-95에서 쓴 방식 — 보기를 저작하지 않으므로 단어가 늘면 문제도 는다).
- **검증**: `npm test` **194/194**(`test/learning.vocab.test.js` 14개 신설 — 매니페스트와 실제
  파일 개수 대조 · 단어 id가 자기 DAY를 가리키는지 · 표제어 중복 · 필수 필드 · 어근 실재 ·
  죽은 어근 · 예문에 표제어 포함 · 모든 DAY가 보기 4개를 만들 수 있는지 · 시드 재현성 ·
  로더의 경로 검증 · **단어 파일 정적 import 금지**). **버그를 일부러 되살려 빨간불 확인**:
  ①session.js에 단어 파일 정적 import 추가 ②매니페스트 count를 49로 조작 ③안 쓰는 어근 추가
  ④없는 어근 참조 — 네 경우 모두 빨간불, 복구 후 194/194.
  헤드리스 브라우저로 30항목 확인(부팅~인트로에서 단어 파일 미요청 · DAY 진입 시에만 동적
  로드 · 다른 DAY는 안 받음 · 어근 칩/힌트/예문 렌더 · 카드 앞뒤 이동 · 50문제 완주 · 정답/오답
  표시 · 결과 정답률 · 틀린 단어만 다시 보기 · 주소 직접 접속 · **로딩 중 이탈해도 다른 화면
  위에 카드를 안 그림**). 기존 회귀 스위트(`scripts/verify.cjs`)도 전부 통과.
- **다음 단계(확정 아님)**: SRS 스케줄러 + `/today` 큐(M2) → 계정별 저장 테이블(M3) →
  통계·스트릭(M4) → 콘텐츠 800 → 2000 → 4000 → 8000(M5). 코드는 M1~M4에서 거의 끝나고
  나머지는 데이터라, 확장 절차(파일 추가 + 매니페스트 한 줄)를 `CLAUDE.md` 동기화 매트릭스에
  적어뒀다.
