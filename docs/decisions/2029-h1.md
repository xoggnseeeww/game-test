### D-84. 초등 영어회화 3건 개선 — 이전 문장 이동·produce 질문 자동 재생·TTS 음성 품질
- **배경**: 사용자가 실제로 써보고 세 가지를 지적: ①챕터에 들어가면 다음 문장으로만
  갈 수 있고 이전 문장으로 돌아갈 수 없다. ②`type: "produce"`(질문·답변형) 문제에서
  질문 문장을 소리 내어 들려주는 기능이 없다(버튼을 눌러야만 들림 — 실제 대화라면
  질문이 먼저 들리는 게 자연스럽다). ③듣기 음성이 기계음처럼 부자연스럽다.
- **① 이전 문장 이동**: `basic-conversation/screens.js`의 `showCard()`와
  `elementary-conversation/screens.js`의 `showRepeatCard()`/`showProduceCard()` 모두
  현재 문장 인덱스가 0보다 클 때만 "◀ 이전 문장" 버튼(기존 `.retry-btn` 재사용, 새
  CSS 없음)을 보여준다. elementary 쪽은 `advance()`와 대칭인 `prev()` 헬퍼를 추가해
  `st.index -= 1` 후 `showCard()`를 다시 부른다 — 복습 모드(`reviewMode`)로 필터링된
  `sentences` 배열 안에서도 그대로 동작한다(인덱스는 항상 현재 활성 배열 기준). basic
  쪽은 기존 "다음 문장" 핸들러와 대칭으로 인라인 처리(그쪽 파일 자체가 아직 헬퍼로 안
  뽑혀 있어 굳이 새로 안 뽑았다).
- **② produce 질문 자동 재생**: `showProduceCard()` 끝에 `if (supportsSpeech())
  speak(card.text, 1)`를 추가해, 카드가 뜨면(처음 진입·이전/다음 이동 전부 포함)
  질문을 한 번 자동으로 읽어준다. "repeat" 카드는 그대로 자동 재생을 안 한다 — 그
  카드는 아이가 듣기 버튼을 눌러 스스로 페이스를 조절하는 게 원래 설계 의도라
  건드리지 않았다.
- **③ TTS 음성 품질**: `js/learning/speech.js`의 `speak()`에 `pickVoice(lang)`을
  추가 — `speechSynthesis.getVoices()`에서 해당 언어의 음성 중 `localService`가
  아닌(네트워크) 음성을 우선 골라 `utterance.voice`에 지정한다. 기기 내장 로컬 음성은
  대체로 기계음에 가깝고, Chrome의 "Google US English" 같은 네트워크 음성이 훨씬
  자연스럽다는 게 흔한 차이라 이 우선순위를 그대로 썼다. 특정 음성 이름을 하드코딩하지
  않은 이유는 기기·브라우저마다 음성 목록이 달라 이름 매칭이 깨지기 쉬워서다 —
  "로컬이냐 아니냐"만 보는 게 기기 간 이식성이 높다. 음성 목록이 아직 비동기 로드
  전이면(Chrome 특성) `matching`이 빈 배열이라 `voice`가 `null`로 남고, 그때는 그냥
  브라우저 기본 음성으로 재생된다 — 별도 대기 로직은 추가하지 않았다(다음 재생부터는
  목록이 채워져 있어 자연스럽게 좋은 음성으로 바뀐다). `speak()`가 두 도구
  (basic-conversation·elementary-conversation) 공용이라 이 개선이 자동으로 둘 다에
  적용된다.
- **검증**: `npm test` 147/147(로직 변경 없음, 순수 UI/음성 선택 추가). 헤드리스
  브라우저: (1) 두 도구 모두 1번째 문장엔 이전 버튼이 없고 2번째부터 생기는지, 클릭
  시 인덱스가 정확히 하나 줄어드는지 확인. (2) produce 카드에서만
  `speechSynthesis.speak()`가 자동 호출되고 repeat 카드에서는 호출되지 않는지 확인
  (중급 6문장 중 정확히 2번 — produce 문장 개수와 일치). (3) 콘솔 에러 없음. 음성
  품질 자체(③)는 실제 사람 귀로 들어야 판단 가능해 헤드리스로는 "voice 선택 로직이
  던지지 않고 동작하는지"까지만 확인했다 — 실제 자연스러움은 배포 후 실기기 확인이
  필요하다.
- **배포 후 확인 필요**: 실기기(특히 안드로이드 Chrome)에서 듣기 버튼을 눌러 음성이
  실제로 예전보다 자연스러워졌는지 확인. 기기에 따라 네트워크 음성이 아예 없을 수도
  있어(오프라인이거나 OS에 TTS 엔진이 로컬만 설치된 경우) 그때는 개선 체감이 없을 수
  있다 — 그 경우도 에러 없이 기존 동작(로컬 음성)으로 조용히 폴백된다.
