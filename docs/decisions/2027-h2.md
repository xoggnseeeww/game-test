### D-60. 학습(외국어 연습) 카테고리 신설 — 어린이 모드 파일럿 하나, 브라우저 내장 TTS/STT만
- **선택**: 사용자가 준비한 영어 학습 웹앱 로드맵(어르신/어린이 대상, Next.js+Supabase+PG결제
  풀스택 기획, 총 7단계)을 이 저장소의 세 번째 카테고리(심리테스트·미니게임에 이어 "학습")로
  대폭 축소해서 적용했다. `registerGame`/`listGames`를 그대로 복사한
  `registerLearning`/`listLearning`을 라우터에 추가하고, `js/learning/greeting/`(인사/기분
  표현, 어린이 모드) 하나만 v1으로 만들었다.
- **왜 새 레지스트리를 안 만들고 게임 레지스트리를 복사했나**: 학습 콘텐츠도 게임처럼 "결과가
  어떤 테스트 점수에 반영되는 하위 단계가 아니라 그 자체로 콘텐츠"라 모양이 같다. 세 번째
  레지스트리를 처음부터 다르게 설계할 근거가 없었다 — 다르게 다뤄야 할 이유가 생기면 그때
  갈라진다.
- **로드맵과 크게 갈라진 지점들**(전부 사용자가 "요금제는 나중에" 외의 항목도 함께 승인):
  - Next.js/Supabase/Vercel로 이관하지 않음 — 지금 스택(빌드 없는 정적 SPA) 그대로.
  - TTS/STT는 로드맵 3-2가 "초기 무료 단계"로 이미 지목한 브라우저 내장 API
    (`speechSynthesis`/`SpeechRecognition`)만 쓴다. 로드맵이 같이 제안한 "확장형 어댑터
    패턴"(공급자 교체 대비)은 지금 만들지 않았다 — 공급자가 하나뿐인 시점에 인터페이스부터
    만드는 건 쓰이지 않는 추상화다. 두 번째 공급자가 실제로 필요해지면 그때 `speak`/`listen`
    두 함수를 인터페이스 경계로 삼는다.
  - 로그인·학습기록 DB·SRS·결제 전부 보류 — 전부 영속 저장이 전제인데, 이 앱은 부부 체크의
    KV 하나만 예외로 두고 나머지는 철저히 무상태(`CLAUDE.md`)라 가볍게 예외를 늘리지 않았다.
  - 스티커북/Streak 같은 날짜에 걸친 보상 체계도 없음 — 세션 내 완료 이펙트(🎉)까지만.
- **어린이 모드부터 만든 이유**: `AskUserQuestion`으로 확인 — 어르신/어린이 두 UX 원칙이 서로
  다르고(전자는 대형 버튼·고대비·한글 발음 가이드, 후자는 캐릭터·미니멀 텍스트), 둘 다 동시에
  만들면 범위가 두 배가 된다. 어린이 모드가 더 작고 검증하기 쉬워 먼저 선택됐다.
  어르신 모드 추가 시 어떻게 붙일지는 `docs/learning-architecture.md` §3-5에 미리 적어뒀다.
- **잘라낸 것들을 나중에 어떻게 붙일지**: 짧게 말하면 여기서 다시 논의하지 않는다 — 전부
  `docs/learning-architecture.md` §3에 항목별로(로그인, 어댑터 패턴, SRS, 결제, 어르신 모드,
  광고 슬롯) 구체적인 재도입 경로를 적어뒀다. 이 저장소 관례상(NumPath 마을 D-54/55처럼)
  되돌리거나 미룬 접근은 기록해두고 다시 원점에서 논의하지 않는다 — 다음에 이 카테고리를
  만지는 세션은 그 문서를 먼저 읽는다.
- **검증**: `test/learning.score.test.js` 신설(유사도·피드백 경계·문장 데이터 정합성),
  `npm test` 140/140(135 + 학습 채점 테스트 5개). 헤드리스 브라우저(`playwright`, 가짜 `SpeechRecognition` 주입)로
  목록→상황→문장 5개 전체 진행→완료→재시작까지 실제 클릭으로 확인 — 실제 STT/TTS 자체는
  마이크·네트워크가 없는 샌드박스라 검증 못 했다(`docs/learning-architecture.md` §4).

### D-61. 문장 카드에 마스코트 SVG 일러스트 + 건너뛰기 버튼 추가
- **선택**: 사용자가 "상황별 그림·캐릭터 이미지"와 "원하면 체크하고 다음으로 넘어가는 기능"을
  요청 — 카드의 emoji 자리를 `js/learning/mascot.js`의 인라인 SVG 마스코트로 바꾸고, 듣기/
  말하기를 강제하지 않는 건너뛰기 버튼(`#learning-skip`, "✓ 이미 할 수 있어요 · 다음 문장")을
  항상 보여준다.
- **왜 외부 이미지 파일이 아니라 인라인 SVG로 그렸나**: 이 저장소엔 이미지 생성 도구·파이프라인이
  없다(og-image PNG 정도가 유일한 예외이고 그것도 Playwright로 한 번 구운 정적 파일이다).
  캐릭터를 실제 삽화로 만들려면 사람이 그리거나 외부 이미지 생성 서비스가 필요한데, 지금은
  둘 다 없다 — 대신 얼굴 하나(원+눈)에 표정(입 모양)·소품(우는 눈물, 반짝임, 하트, 손 흔들기)을
  코드로 조합해서 "그림처럼 보이는" 최소 비용 대안을 택했다. 상황이 늘어도 새 이미지 파일을
  안 만들어도 되고, `mood` 문자열 하나로 기존 표정·소품 조합을 재사용할 수 있다.
- **처음에 "handshake"(손 모양 소품)로 만들었다가 "friendly"(하트 소품)로 바꾼 이유**: 실제
  헤드리스 브라우저로 렌더 결과를 스크린샷으로 확인해보니, 얼굴 옆에 작은 원 하나만 떠 있는
  모양이라 "악수"로 안 읽히고 혼란스러웠다(정확히는 두 번째 작은 머리처럼 보였다). 이 스타일
  (단순 도형 조합)로는 손을 맞잡는 동작을 표현하기 어렵다고 판단해, 더 명확하게 읽히는 하트
  소품으로 바꿨다 — "만나서 반가워요"라는 문장의 감정(친근함)은 하트로도 충분히 전달된다.
- **건너뛰기가 마이크 성공/실패 이후엔 사라지는 이유**: 결과가 나오면 "다음 문장" CTA 버튼이
  이미 같은 동작(다음으로 이동)을 하므로, 같은 역할의 버튼 두 개를 동시에 보여주지 않으려고
  결과가 나오는 순간 건너뛰기 버튼을 숨긴다. 시도 전(듣기/말하기를 하기 전)에는 계속 보여서,
  이미 아는 문장이면 아예 시도 없이 바로 넘어갈 수 있다.
- **검증**: `test/learning.mascot.test.js` 신설(마스코트가 실제 svg 마크업인지 · 모르는 mood가
  조용히 안 죽고 기본값으로 대체되는지 · 문장 데이터의 mood가 전부 실재하는 마스코트를
  가리키는지). `npm test` 143/143. 헤드리스 브라우저로 5개 카드 전부 스크린샷 확인 +
  건너뛰기 버튼만으로 마이크 없이 완료 화면까지 도달하는 것 확인.

### D-62. 학습의 레지스트리·목록 화면 제거 — "카탈로그"가 아니라 "하나의 공부 도구"로 정정
- **선택**: D-60에서 만든 `registerLearning`/`listLearning`(`js/core/router.js`)과 목록 화면
  (`learning-list`, 홈 "학습" 카드 → 카드 그리드 → 상황 화면)을 걷어냈다. 홈의 "학습" 카드가
  이제 목록 없이 `learning-greeting` 화면으로 곧장 간다. `js/learning/greeting/index.js`의
  카탈로그용 `card` 메타데이터(emoji/color/name/desc)도 같이 삭제 — 아무도 안 읽는다.
- **왜 되돌렸나**: 사용자 피드백 원문 — "학습에 하나의 도구로 만들어줘야지 목차별로 다
  나열할 수가 없잖아. 하나의 공부 창이 되는거지." 심리테스트·미니게임은 서로 독립적인
  콘텐츠라 "목록에서 하나 골라 들어간다"는 카탈로그 모델이 맞다(실제로 서로 다른 결과
  유형·다른 게임 규칙을 가진 완전히 별개의 것들이다). 학습은 다르다 — 상황(인사, 나중엔
  공항·병원 등)이 하나의 커리큘럼을 이루는 하위 단원이라, 사용자가 매번 홈까지 돌아와
  카드를 다시 고르게 하면 "여러 앱을 오가는" 느낌이 된다. `registerGame`을 그대로 복사한
  게 D-60의 실수였다 — 게임과 "결과가 테스트 점수에 안 들어간다"는 점은 같았지만, "서로
  독립적인가"는 안 같았다. 폴더 구조(`data.js`/`score.js`/`screens.js`/`index.js`)까지
  되돌릴 필요는 없었다 — 콘텐츠 분리 자체는 여전히 유효하고, 카탈로그로 노출하는 방식만
  틀렸다.
- **경로 변경**: `/learning/greeting` → `/learning` (목록이 없어졌으니 하위 경로일 이유가
  없다). 이 화면은 이번 세션에 새로 만든 것이라 아직 배포된 적이 없어 경로/화면 id를 바꿔도
  "이미 열려 있는 탭의 뒤로가기가 깨진다"는 절대 규칙(`CLAUDE.md`, 이미 배포된 화면 대상)에
  걸리지 않는다.
- **다음 상황을 어떻게 이을지는 아직 안 정했다**: 상황이 하나뿐이라 실전 검증 전이다.
  방향만 `docs/learning-architecture.md` §3-5에 적어뒀다 — 새 카드를 또 만드는 대신 같은
  학습 화면 흐름 안에서 다음 상황으로 잇는 쪽. 두 번째 상황을 실제로 만들 때 확정한다.
- **검증**: `npm test` 143/143(개수 불변 — 화면 하나가 사라지고 검사 목록도 같이 줄었다).
  헤드리스 브라우저로 홈 → 학습 카드 클릭 → 목록 없이 바로 문장 카드 도착, 뒤로가기 →
  홈, `/learning` 직접 접속까지 확인.

### D-63. 학습을 2단(도구 카탈로그 → 도구 내 목차)으로 재정정 — D-62의 "목록 완전 삭제"를 한 단 위로만 되돌림
- **선택**: D-62에서 없앤 레지스트리·목록 화면을 다시 만들되, 이번엔 대상이 다르다 — D-60은
  "상황"(`greeting`)을 최상위에 등록했었고, D-62는 그 최상위 등록 자체를 없앴다. D-63은
  "**도구**"(`basic-conversation`, 사용자 표현으로 "기초 영어회화")를 최상위에 등록하고,
  상황(이제 "챕터"라고 부른다)은 그 도구 **안의** 목차 데이터로 내렸다. 결과 구조:
  홈 → 학습 목록(도구 카드) → 도구의 목차(챕터 카드) → 챕터 하나(문장 연습).
  `js/core/router.js`에 `registerLearning`/`listLearning`을 다시 추가(`registerTest`와
  대칭, 이번엔 진짜 대칭이다 — 도구가 서로 독립적이라는 전제가 맞는다). `js/screens/home.js`에
  `renderLearningList()`도 다시 추가. `js/learning/greeting/`을
  `js/learning/basic-conversation/`으로 옮기고, `data.js`는 평평한 `SENTENCES` 대신
  `CHAPTERS`(챕터 배열, 챕터마다 `sentences`) 구조로 바꿨다. `index.js`가
  `CHAPTERS.map()`으로 챕터별 화면(`learning-basic-conversation-<챕터id>`)을 자동
  생성한다 — 챕터가 늘어도 `index.js`를 고칠 필요가 없다.
- **D-62가 뭘 놓쳤나**: 사용자의 "목차별로 나열할 수 없다, 하나의 공부 창이 되는 거다"라는
  피드백을 "학습 카테고리 전체에 카탈로그가 없어야 한다"로 과잉 해석했다. 실제로는 "상황 하나
  하나가 홈 레벨 카드가 되면 안 된다"는 지적이었고, 곧바로 이어진 "학습 카테고리 안에 다른
  공부 도구도 넣을 거다, 심리테스트 들어가면 종류별로 테스트 있듯이"라는 두 번째 메시지가
  정확한 목표 구조를 알려줬다 — 도구 레벨엔 카탈로그가 있어야 하고(심리테스트와 대칭), 그
  안의 상황(챕터) 레벨엔 목차형 흐름이 있어야 한다(사용자 표현 그대로 "목차별로 공부"). 되돌림
  두 번이 짧게 이어졌지만, 첫 번째 되돌림(D-62)이 틀린 게 아니라 **범위가 부족**했던
  것이라 D-62 자체를 무효로 보지 않는다 — "상황을 홈 최상위 카드로 노출하지 않는다"는 여전히
  유효하고, D-63은 그 위에 "도구 레벨 카탈로그"만 새로 얹었다.
- **경로**: `/learning/greeting` → `/learning/basic-conversation`(목차) +
  `/learning/basic-conversation/greeting`(첫 챕터). `/learning`은 이제 다시 도구 목록이다.
  전부 이번 스프린트에 새로 만든 화면이라 배포 이력이 없어 경로/id를 자유롭게 바꿔도
  "이미 열린 탭의 뒤로가기가 깨진다"는 규칙에 걸리지 않는다.
- **검증**: `test/learning.score.test.js`·`test/learning.mascot.test.js`를 `CHAPTERS` 구조에
  맞게 갱신(챕터 id 중복 검사·챕터별 문장 id 중복 검사 추가). `npm test` 144/144(챕터별
  검사 1개 순증). 헤드리스 브라우저로 홈 → 학습 목록 → 기초 영어회화 목차 → greeting 챕터
  → 건너뛰기 5회 → 완료 → "목차로 돌아가기"까지, 그리고 뒤로가기를 3단 전부(챕터→목차→목록→
  홈) 눌러서 각 단계 타이틀·주소가 맞는지 확인.

### D-64. 마스코트 일러스트 제거 · 인사/기분 표현 30문장으로 확장 · 챕터 3개 추가 · 한글 해석 폰트 확대
- **마스코트 제거(D-61 되돌림)**: 사용자가 실제 렌더 결과를 보고 "위에 이모티콘이 별로인거
  같아서 빼고 나중에 이미지 추가하게 되면 따로 넣자"고 판단 — `js/learning/mascot.js`,
  문장 데이터의 `mood` 필드, `test/learning.mascot.test.js`를 전부 삭제했다. 코드로 그린
  조합형 SVG 얼굴이 실물로는 만족스럽지 않았다는 뜻이라, 나중에 이미지를 붙일 땐 이 방식을
  재사용하지 않고 실제 이미지 에셋으로 새로 접근한다는 전제를 남겼다
  (`docs/learning-architecture.md` §2). `styles.css`의 `.cover .mascot` 규칙도 죽은 코드라
  같이 지웠다.
- **인사/기분 표현을 5문장 → 30문장으로 확장**: 인사(Hello/Good morning/Good night 등)·
  감정 표현(happy/sad/angry/tired/hungry/thirsty/sleepy/scared/excited/surprised/bored/
  okay)·기본 대화(이름 묻기/알려주기/또 만나요/고마워요/미안해요/실례합니다 등)로 범주를
  넓혔다. id는 전부 `kebab-case`로 문장 내용을 그대로 딴 값(`good-morning`, `whats-your-name`
  등)이라 챕터 안에서 무엇을 가리키는지 코드만 봐도 알 수 있다.
- **챕터 3개 추가**: 로드맵 1-2가 어린이 특화로 지목한 나머지 세 상황(동물/음식, 학교/놀이터,
  자기소개)을 각 8문장씩 채워 `CHAPTERS`에 추가했다 — 새 챕터 추가가 데이터만 늘리면 되는지
  실전으로 검증된 계기이기도 하다(`js/main.js`·라우터·목차 화면 전부 무수정).
- **한글 해석 폰트 확대**: 문장 카드의 `<p>`(한글 뜻)에 `cover-ko` 클래스를 붙이고
  13px(`.cover p` 공용 값) → 17px로 키웠다. `.cover p`(0,1,1)보다 `.cover-ko`(0,1,0) 단독
  선택자가 상세도가 낮아 그냥 두면 밀린다는 걸 확인하고 `.cover p.cover-ko`(0,2,1)로 상세도를
  올려서 확실히 이기게 했다 — 다른 테스트 인트로의 `.cover p`(부가 설명, 13px 유지)는
  건드리지 않았다.
- **검증**: `npm test` 141/141(마스코트 검사 3개 감소: 144 → 141). 헤드리스 브라우저로
  목차 화면의 4개 챕터·문장 개수 표기(30/8/8/8) 확인, `getComputedStyle`로 `.cover-ko`가
  실제 17px로 렌더되는지 확인, 마스코트 svg가 더 이상 안 그려지는지 확인, 인사/기분 표현
  30문장 전체와 나머지 세 챕터(각 8문장)를 건너뛰기로 완주해 문장 개수·완료 문구가
  정확히 일치하는지 확인. 스크린샷으로 실제 카드 레이아웃 육안 확인.

### D-65. 챕터 목차를 일상대화 위주로 재구성 — 어린이 애니메이션 참고
- **선택**: 사용자 요청 "일상대화 위주로 카테고리를 짜줘. 어린이 애니메이션 참고해서"에
  따라 `js/learning/basic-conversation/data.js`의 `CHAPTERS`를 재구성했다.
  `animals-food`(동물/음식)·`school-playground`(학교/놀이터)를 지우고, 대신 하루 일과를
  따라가는 6개(`morning-routine` 아침 일과·`family` 가족 이야기·`playing-with-friends`
  친구랑 놀기·`meal-time` 밥 먹을 때·`bath-bedtime` 목욕·잠자리·`weather` 날씨 이야기)로
  바꿨다. `greeting`(인사/기분 표현, 30문장)과 `self-intro`(자기소개)는 그대로 뒀다.
  최종 8챕터: 인사/기분 표현(30) · 아침 일과(8) · 가족 이야기(8) · 친구랑 놀기(10) · 밥
  먹을 때(8) · 목욕·잠자리(8) · 날씨 이야기(8) · 자기소개(8).
- **왜 "동물/음식"·"학교/놀이터" 대신 하루 일과인가**: 원래 두 챕터는 로드맵 1-2가 준
  단어 카테고리를 그대로 옮긴 것이라, 문장도 "This is a rabbit"(사물 명명) 같은 어휘
  나열에 가까웠다. 뽀로로·타요·페파피그 같은 유아 애니메이션은 어휘가 아니라 **하루
  일과 하나(아침에 일어나기, 친구랑 놀기, 밥 먹기, 목욕하고 자기)를 에피소드로** 삼고, 그
  안에서 캐릭터끼리 실제로 주고받는 말(Let's play! / Can I have more? / Watch this!)을
  반복해서 들려준다 — 그 결을 그대로 옮겼다. 동물/음식·학교/놀이터가 다루던 소재(먹기,
  친구·놀이)는 없어지지 않고 `meal-time`·`playing-with-friends`에 대화체로 흡수됐다.
- **문장 재사용**: `playing-with-friends`는 옛 `school-playground`의 놀이 관련 문장
  (Let's play! / Can I play too? / It's my turn!)을 그대로 가져오고 새 문장을 더해 10개로
  늘렸다 — 학교라는 장소보다 "친구랑 노는 상황" 자체가 일상대화에 더 가깝다고 봤다.
  `meal-time`은 옛 `animals-food`의 "This is yummy!"만 살리고 나머지는 실제 식사 시간에
  주고받는 대화(Let's eat! / Can I have more? / I'm full.)로 새로 썼다.
- **경로**: `/learning/basic-conversation/animals-food`·`/school-playground`는 사라지고
  `/morning-routine`·`/family`·`/playing-with-friends`·`/meal-time`·`/bath-bedtime`·
  `/weather`가 새로 생겼다. 전부 아직 배포된 적 없는 화면이라 경로를 자유롭게 바꿔도
  기존 규칙(화면 id·경로 불변)에 걸리지 않는다.
- **검증**: `npm test` 141/141(챕터/문장 구조가 전부 데이터에서 자동 검증되는 제네릭
  테스트라 챕터를 갈아 끼워도 테스트 파일 자체는 무수정). 헤드리스 브라우저로 목차의
  8개 챕터·문장 개수 표기(30/8/8/10/8/8/8/8)를 확인하고, 8개 챕터 전부를 건너뛰기로
  완주해 각 챕터의 완료 문구가 실제 문장 개수와 일치하는지 확인. 스크린샷으로 목차
  레이아웃 육안 확인.
