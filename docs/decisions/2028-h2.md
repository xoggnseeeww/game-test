### D-76. 초등 영어회화 UX 마찰 4건 수정 — 학년 선택 건너뛰기·produce 힌트·문법 라벨·마이페이지 weak 총합
- **배경**: D-75로 초등 영어회화의 콘텐츠 엄밀함(문법 진행·반복·produce)을 보강한 뒤,
  사용자가 "구조적으로 공부가 정말 쉽게된다고 말할수있나?"라고 다시 물었다. 이번엔
  콘텐츠가 아니라 UX 마찰 얘기라 다른 문제였고, 정직하게 답하면 넷이 걸렸다:
  ① 학년이 저학년 하나뿐인데 "학년을 골라주세요" 화면을 거치게 해서 클릭만 늘고 얻는
  게 없었다. ② produce 문장이 아무 참고 없이 질문만 던져서, 정답이 하나가 아닌 개방형
  질문에 백지에서 답해야 하는 아이가 얼어붙을 위험이 있었다. ③ `grammar` 태그가
  콘텐츠 저작·반복 검사용 내부 장치일 뿐 학습자 화면엔 안 보여서, 지금 뭘 배우는지
  의식하지 못했다(메타인지 스캐폴딩 없음). ④ "헷갈렸던 문장만 복습하기"가 그 챕터의
  완료 화면에서만 뜨고 다른 데서 모아볼 방법이 없어, 그 순간을 놓치면 복습 진입로
  자체가 사라졌다. 사용자가 "넷 다 반영해서 고쳐줘"로 확정.
- **선택 1 — 학년 선택 건너뛰기**: `learning-elementary` 화면(학년 선택)에
  `guard: () => GRADES.length === 1 ? "learning-elementary-lower" : null`를 달아,
  학년이 하나뿐이면 그 학년의 챕터 목차로 곧장 건너뛴다. 학년이 늘어나면(길이 !== 1)
  guard가 저절로 꺼져서 선택 화면이 다시 뜬다 — 새 조건 분기를 코드에 남기지 않고
  라우터의 기존 guard 계약만 썼다. 부작용: 챕터 목차 화면의 "뒤로가기"가 다시
  `learning-elementary`로 가면 guard가 곧장 되튕겨서 뒤로가기가 안 먹는 것처럼 보이는
  루프가 생겼다 — `renderElementaryChapters`가 학년이 하나뿐일 땐 뒤로가기 대상을
  `learning-list`(학습 목록)로 바로 잡게 해서 고쳤다.
- **선택 2 — produce 카드에 시도 전 hint**: 문장 데이터에 `hint`(문장 시작 조각, 예
  "I bring ___.")를 추가했다 — 정답은 아니고 어디서부터 말을 시작하면 될지 감만
  준다. `test/learning.elementary.test.js`에 "produce 문장은 hint가 있다" 검사를
  추가해 앞으로 추가되는 produce 문장도 빠뜨리지 않게 했다.
- **선택 3 — 연습 카드에 문법 라벨 노출**: `renderChapter` 안에 `grammarLabel(card)`
  헬퍼를 추가해 `grade.grammarPoints`에서 그 문장의 `grammar` id에 해당하는 라벨을
  찾아 "🔤 오늘의 문법: 조동사 can (능력·허락)" 형태로 카드마다 보여준다(repeat·produce
  둘 다). 문법 태그 자체는 안 바꿨다 — 원래 저작 시점의 내부 장치였던 걸 화면에도
  드러낸 것뿐이다.
- **선택 4 — 마이페이지에 헷갈린 문장 총합 노출**: `renderMyPage`의 `renderLearning()`이
  `state.learning`을 도구에 무관하게 집계하던 기존 방식(D-70) 그대로, `ch.weak || {}`의
  키 개수를 더해 총합을 하나 더 보여준다 — 여기서도 개별 학습 도구를 import하지 않는다
  (weak가 없는 도구는 `|| {}`로 0이 된다). 다만 이 화면에서 바로 복습 화면으로 뛰어들
  수는 없다 — "헷갈렸던 문장만 복습하기" 버튼은 여전히 그 단계의 완료 화면
  (`showDone()`)에서만 나타나므로, 문구를 "해당 단계를 한 번 더 끝까지 풀면 다시
  떠요"로 정직하게 적었다(처음엔 "다시 들어가면 이어갈 수 있다"고 썼다가 실제 동작과
  안 맞아 고쳤다 — 마이페이지에서 특정 단계로 직접 딥링크하는 건 이번 범위 밖).
- **검증**: `npm test` 147/147(신규 hint 검사 1개 추가). 헤드리스 브라우저로
  `/learning/elementary` 접속 시 학년 선택 없이 곧장 `/learning/elementary/lower`로
  이동하는지, 챕터 목차의 뒤로가기가 루프 없이 학습 목록으로 가는지, 연습 카드
  (repeat·produce 둘 다)에 문법 라벨이 뜨는지, produce 카드에 hint가 뜨는지 확인.
  가짜 STT로 오답을 하나 만들고 마이페이지에 진입해 "헷갈렸던 문장 1개가 남아
  있어요" 문구가 뜨는지 확인. 콘솔 에러 없음.

### D-77. 저학년 나머지 챕터 3개 완성 — 교실에서·쉬는 시간·좋아하는 것
- **배경**: D-75·D-76으로 챕터 하나(학교 가는 날)에서 문법 태그·반복·produce·힌트·문법
  라벨·마이페이지 노출까지 메커니즘이 전부 실제로 동작하는 걸 확인한 뒤, 사용자가
  "이제 큰 그림 그렸으니까 내용 채워보자"고 요청 — 저학년의 나머지 챕터를 채우는 단계.
- **선택**: `교실에서`(🏫)·`쉬는 시간`(⏰)·`좋아하는 것`(⭐) 3챕터를 학교 가는 날과 같은
  틀(기본 10·중급 6·심화 4, 총 20문장)로 추가해 저학년이 4챕터·80문장이 됐다. 문법은
  챕터마다 무조건 하나씩 새로 늘리지 않았다 — `교실에서`가 G5(조동사 should)를,
  `쉬는 시간`이 G6(과거형)를 새로 도입하고, `좋아하는 것`은 **새 문법 없이** G1~G6를
  다른 소재(취미·과목)로 다시 섞어 쓰기만 한다 — "반복이 매 챕터 새 문법 하나씩"이
  아니라는 걸 보여주는 사례로 일부러 이렇게 짰다. 챕터마다 이전 챕터의 문법을 최소
  하나는 재사용해서(예: `쉬는 시간`의 "Can I play with you?"가 `학교 가는 날`의 G3를,
  `좋아하는 것`의 "I shouldn't spend too much time on games."가 `교실에서`의 G5를
  재사용) `test/learning.elementary.test.js`의 반복 규칙 검사가 챕터 2번째부터 처음으로
  실제 데이터에 대해 돌아갔다(D-75에선 챕터가 하나뿐이라 이 검사가 트리거되지 않았다).
- **produce 문장 hint도 챕터마다 같은 규칙으로**: 새로 추가한 produce 문장 6개
  (챕터당 2개 × 3챕터)도 전부 시도 전 hint를 달았다(D-76에서 정한 규칙 그대로) —
  `test/learning.elementary.test.js`의 hint 검사가 그대로 잡아준다.
- **검증**: `node -e`로 4챕터 전부 기본 10·중급 6·심화 4(총 80문장), 챕터 안 문장 id
  중복 0건 확인. `npm test` 147/147 — 특히 "두 번째 챕터부터는 이전 챕터에서 이미 나온
  grammar를 최소 1문장 이상 재사용한다" 테스트가 이번에 처음으로 3개 챕터(classroom·
  recess·favorites)에 대해 실제로 검증됐다(전부 통과, 테스트 파일 자체는 무수정).
  헤드리스 브라우저로 학습 목록 카드 4개(각각 "기본 10 · 중급 6 · 심화 4") 확인,
  4챕터 전부 심화 단계를 건너뛰기로 완주해 완료 문구가 정확한지 확인. 콘솔 에러 없음.
- **다음 단계**: 저학년은 이제 목차가 다 찼다(4챕터). 다음은 중학년(3~4학년) — 처음
  제안한 목차(수업과 과제·친구 관계·방과 후 생활·우리 동네)와 새 문법 순서
  (MIDDLE_GRAMMAR_POINTS)부터 잡아야 한다.

### D-78. 중학년(3~4학년) 챕터 4개 신설 — 수업과 과제·친구 관계·방과 후 생활·우리 동네
- **배경**: D-77로 저학년(4챕터·80문장)이 다 찬 뒤, 사용자가 "진행"으로 다음 단계(처음
  제안했던 목차의 중학년)를 확정.
- **선택**: `MIDDLE_GRAMMAR_POINTS`를 새 배열로 두고(G7~G11 — 현재형 복습·have to/must·
  미래형·비교급·현재진행형), 저학년과 번호가 안 겹치게 이어 붙였다. G7이 저학년 G2
  (일반동사 현재형)와 개념은 겹치지만 **의도적으로 새 id로 다시 정의**했다 — 학년
  트랙이 서로 독립적이어야 한다는 게 D-75의 전제라, 중학년이 저학년의 grammarPoints를
  참조하게 하면 두 배열이 실질적으로 하나로 묶여서 나중에 학년 하나만 따로 손보기
  어려워진다. 챕터는 처음 제안한 목차 그대로 `수업과 과제`(📚)·`친구 관계`(🤝)·
  `방과 후 생활`(🎨)·`우리 동네`(🏘️) 4개, 저학년과 같은 틀(기본 10·중급 6·심화 4,
  총 20문장씩)로 만들어 중학년도 4챕터·80문장이 됐다. `우리 동네`는 저학년의 `좋아하는
  것`과 같은 이유로 새 문법을 안 늘리고 G7~G11을 새 소재(심부름·동네)로만 재사용한다.
- **문법 진행 방향**: 저학년이 be동사·일반동사·can·there is/are·should·과거형(G1~G6)
  이었다면, 중학년은 의무(have to/must)·미래형·비교급·현재진행형(G7~G11)로 넘어가서
  "간단한 사실 진술"에서 "계획·의무·비교가 들어간 좀 더 복잡한 문장"으로 이어진다 —
  애초에 중학년을 "감정·의견 표현이 늘고 문법이 조금 복잡해짐"으로 설계했던 것과
  맞춘 방향(초등학생 목차 최초 제안 때 기록).
- **검증**: `node -e`로 저학년 4챕터 + 중학년 4챕터 전부 기본 10·중급 6·심화 4(총
  160문장), 챕터 안 문장 id 중복 0건 확인. `npm test` 147/147(제네릭 테스트라 무수정 —
  학년이 하나 더 늘어도 그래도 통과, 반복 규칙 검사가 중학년 4챕터에 대해서도 별도로
  돈다). 헤드리스 브라우저로 `/learning/elementary`가 이제 학년 2개를 보여주는지(D-76의
  1개일 때만 건너뛰는 guard가 저절로 꺼졌는지) 확인, 중학년 챕터 목차·문장 개수 확인,
  4챕터 전부 심화 단계를 건너뛰기로 완주해 완료 문구와 문법 라벨이 정확한지 확인.
  콘솔 에러 없음.
- **다음 단계**: 고학년(5~6학년) — 처음 제안한 목차(의견 나누기·꿈과 진로·요즘 이슈·
  여행과 경험)와 새 HIGH_GRAMMAR_POINTS부터. 고학년까지 채워지면 초등 영어회화 3개
  학년이 전부 완성된다.

### D-79. 고학년(5~6학년) 챕터 4개 신설 — 의견 나누기·꿈과 진로·요즘 이슈·여행과 경험
- **배경**: D-78로 중학년(4챕터·80문장)이 다 찬 뒤, 사용자가 "진행"으로 다음 단계(처음
  제안했던 목차의 고학년)를 확정. 이걸로 초등 영어회화의 학년 3단계가 전부 채워진다.
- **선택**: `HIGH_GRAMMAR_POINTS`를 새 배열로 두고(G12~G15 — 현재형 복습·최상급·조건문·
  관계대명사 who/that), 저학년·중학년과 번호가 안 겹치게 이어 붙였다(같은 이유는
  MIDDLE_GRAMMAR_POINTS 주석·D-78 참고). 챕터는 처음 제안한 목차 그대로 `의견
  나누기`(💬)·`꿈과 진로`(🌟)·`요즘 이슈`(🌍)·`여행과 경험`(✈️) 4개, 이전 학년과 같은
  틀(기본 10·중급 6·심화 4, 총 20문장씩)로 만들어 고학년도 4챕터·80문장 — 초등 영어회화
  전체가 3개 학년·12챕터·240문장이 됐다.
- **문법 진행 방향**: 저학년(be동사·일반동사·can·there is/are·should·과거형)→중학년
  (의무·미래·비교·현재진행형)에 이어, 고학년은 최상급·조건문(if)·관계대명사로 넘어가서
  "계획·의무·비교가 들어간 문장"에서 "의견·조건·관계절이 들어간 복문"으로 이어진다.
  `꿈과 진로`가 조건문을 도입할 때 "If I study hard, I will become a scientist"처럼
  진로 얘기와 자연스럽게 엮이도록 짰다(조건-결과 구조가 "이렇게 하면 이렇게 될 거예요"라는
  진로 얘기의 화법과 맞아떨어진다). `여행과 경험`은 저학년 `좋아하는 것`·중학년 `우리
  동네`와 같은 이유로 새 문법 없이 G12~G15만 재사용한다.
- **검증**: `node -e`로 3개 학년·12챕터 전부 기본 10·중급 6·심화 4(총 240문장), 챕터
  안 문장 id 중복 0건 확인. `npm test` 147/147(제네릭 테스트라 무수정 — 반복 규칙
  검사가 고학년 4챕터에 대해서도 별도로 통과). 헤드리스 브라우저로 `/learning/
  elementary`가 학년 3개를 보여주는지, 고학년 챕터 목차·문장 개수 확인, 4챕터 전부
  심화 단계 건너뛰기로 완주해 완료 문구·문법 라벨 확인, produce 문장 hint("The best
  movie is ___.")가 뜨는지 확인. 콘솔 에러 없음.
- **다음 단계**: 학년 3단계가 다 찼다. 이제부터는 (1) 각 학년 안에 챕터를 더 늘리거나,
  (2) 진짜 다중 턴 대화형 도구(§3-7, 아직 미착수)로 넘어가는 두 방향 — 확정 아님, 다음
  요청에서 방향을 정한다.

### D-80. 각 학년에 챕터 하나씩 추가 — 체육 시간·학교 행사·협동과 리더십
- **배경**: D-79로 학년 3단계가 다 찬 뒤, 다음 방향을 두 갈래로 물었다 — (1) 각 학년
  안에 챕터를 더 늘리기 vs (2) 진짜 다중 턴 대화형 도구(§3-7)로 넘어가기. 사용자가
  "1"로 확정.
- **선택**: 학년마다 챕터 하나씩 추가해 전부 4챕터 → 5챕터가 됐다(총 15챕터·300문장).
  - 저학년 `체육 시간`(🏃): 좋아하는 것과 같은 이유로 새 문법 없이 G1~G6만 재사용.
  - 중학년 `학교 행사`(🎉): 새 문법 G16(과거진행형, was/were + -ing) 도입 — 현재형(G7)·
    미래형(G9)·현재진행형(G11)에 이어 "진행형" 계열을 완성한다("I was watching the
    race when it started to rain.").
  - 고학년 `협동과 리더십`(🏆): 새 문법 G17(used to, 과거 습관·상태 회상) 도입 — "I
    used to be shy, but now I speak up." 같은 성장 서사가 리더십 얘기와 잘 맞는다.
  - 세 챕터 다 이전 챕터의 문법을 최소 하나씩 재사용해 반복 규칙을 지켰다(예: 학교
    행사가 have to(G8)·will(G9)을, 협동과 리더십이 최상급(G13)·조건문(G14)·관계대명사
    (G15)를 다시 쓴다).
- **새 문법 id 번호 매기기**: G16(중학년)·G17(고학년)은 "그 학년 배열 안에서 다음
  번호"가 아니라 **지금까지 나온 것 중 가장 큰 번호 다음**을 그대로 이어 붙였다 —
  어느 학년이 먼저 새 챕터를 받을지 미리 알 수 없어서, 학년별로 번호 구간을 나눠두면
  나중에 번호가 꼬인다. `data.js` 헤더 주석에 이 규칙을 명시했다.
- **검증**: `node -e`로 3개 학년·15챕터 전부 기본 10·중급 6·심화 4(총 300문장), 챕터
  안 문장 id 중복 0건 확인. `npm test` 147/147(제네릭 테스트라 무수정 — 반복 규칙
  검사·grammar 유효성 검사가 새 챕터 3개에 대해서도 전부 통과, 새 문법 포인트 G16·G17을
  쓰는 문장이 있는지도 자동 확인됨). 헤드리스 브라우저로 학년별 챕터 목차에 새 챕터가
  포함됐는지, 새 챕터 심화 단계를 건너뛰기로 완주해 완료 문구·문법 라벨(과거진행형/
  used to)이 정확한지 확인. 콘솔 에러 없음.
- **다음 단계**: 확정 아님 — 챕터를 계속 늘릴지(학년당 6번째 챕터), 다중 턴 대화형
  도구(§3-7)로 넘어갈지는 다음 요청에서 다시 판단한다.
