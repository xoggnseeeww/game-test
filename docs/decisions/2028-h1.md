### D-72. 챕터마다 기초 → 심화 2단계 추가 — 원어민 7세 수준 문장까지
- **배경**: 사용자 의견 — "7세쯤 되면 자신의 의견이나 대화의 질이 훨씬 늘어난다고 생각하는데
  지금 만든건 입문용인거같고 단계를 나눠서 원어민 7살정도 되는 친구들이 할수있는 대화까지
  만들어볼까". 지금까지 문장은 전부 "생존 표현" 수준(Let's play! / I'm hungry.)이라, 실제
  원어민 7세가 하는 말(의견·이유·비교·협상·되묻기)과는 격차가 있었다.
- **먼저 제시한 갈림길**: 이 앱의 학습 방식(문장 하나 듣고 그대로 따라 말하기 + 발음 유사도
  채점)은 "정해진 문장을 정확히 반복하기"에 최적화돼 있어서, 진짜 다중 턴 대화(질문→대답→
  되묻기, 정답이 여러 개일 수 있음)를 그대로 담기는 구조적으로 안 맞는다고 짚었다. 두 방향을
  제안: (1) 지금 구조 그대로 각 챕터를 기초/심화로 나눠 심화 문장을 더 길고 의견·이유가
  들어가게 만들기 — 기존 아키텍처로 바로 확장 가능. (2) 진짜 다중 턴 대화형 도구를 새로
  설계하기 — 화면·채점 로직을 다시 만들어야 해서 범위가 훨씬 큼. 사용자가 "지금은 1번,
  대화형 웹앱은 추후에"로 선택했다(`docs/learning-architecture.md` §3-7에 나중에 어떻게
  붙일지 기록).
- **선택**: `js/learning/basic-conversation/data.js`의 문장 객체에 선택적 `level: "advanced"`
  필드를 추가(없으면 기초). 각 챕터의 `sentences` 배열 안에서 기초를 전부 나열한 뒤 심화
  6개씩을 끝에 이었다 — greeting/daily-routine/family-and-me/playground 전부 +6문장씩,
  총 +24문장(112 → 136). 심화 문장은 의견("I think dogs are cuter than cats."), 이유
  ("I'm happy because it's my birthday."), 비교("My brother is older than me."), 협상
  ("Can we play something else?"), 되묻기("Why are you sad?") 패턴을 챕터 소재에 맞게
  하나씩 넣었다.
- **화면은 안 바꿨다**: 레벨 선택 UI나 새 화면을 만들지 않고, 기존 in-place 렌더(`showCard`)가
  그대로 순서대로 넘어가게 뒀다 — 기초를 다 풀면 자연스럽게 심화로 이어진다. 목차 화면의
  카드 설명만 "기초 N · 심화 M"으로 갈라 보여주고(`renderBasicConversationIntro`), 심화
  문장 카드에는 기존 `.cover .tag` 클래스(다른 테스트 인트로가 카테고리 라벨에 쓰던 것,
  예: "직장인 유형검사")를 그대로 재사용해 "심화" 배지를 얹었다 — 새 CSS를 하나도 안 만들고
  됐다.
- **검증**: `node -e`로 챕터별 총 문장·기초/심화 개수(greeting 36=30+6, daily-routine
  38=32+6, family-and-me 30=24+6, playground 32=26+6, 합계 136) 확인. `npm test` 141/141
  (제네릭 테스트라 `level` 필드 추가에도 테스트 파일 무수정 — 챕터/문장 id 중복 검사가 심화
  문장의 새 id도 자동으로 검사한다). 헤드리스 브라우저로 목차 카드 설명이 "기초 N · 심화
  M" 형태로 바뀌었는지, greeting 챕터를 31번째까지 건너뛰었을 때 정확히 그 지점부터 "심화"
  배지가 나타나는지, 4챕터 전부 완주 시 늘어난 문장 개수와 완료 문구가 일치하는지 확인.
  스크린샷으로 심화 카드에 배지가 자연스럽게 얹히는지 육안 확인.

### D-73. 챕터마다 기본/중급/심화 3단계 + 단계 선택 화면 추가
- **배경**: 사용자 의견 — "상황챕터 누르면 기본/심화 고를수있게 하자. 심화 내용이 갑자기
  확 어려워지는건 아닌가 싶기도한데, 기본에 대략 30개, 중급에 대략 30개, 심화에 30개
  이렇게 넣는건 어때". D-72에서 각 챕터에 기초 다음 심화 6문장을 이었더니, 같은 챕터를
  계속 진행하다 기초(생존 표현) → 심화(의견·이유·비교·협상)로 난이도가 한 번에 크게
  뛰는 구간이 생겼다.
- **선택 1 — 단계 선택 화면**: 챕터를 누르면 바로 연습으로 들어가던 것을, 먼저 단계
  (기본/중급/심화)를 고르는 화면(`renderLevelSelect`)이 뜨도록 바꿨다. 3단계를 처음부터
  끝까지 죽 이어 풀어야 하는 게 아니라, 원하는 단계만 골라 반복할 수 있어야 한다는
  판단 — 예를 들어 중급만 반복 연습하고 싶은 아이가 매번 기본 30개를 다시 지나칠 필요가
  없다. 라우팅은 `/learning/basic-conversation/<chapterId>`가 단계 선택(예전엔 연습
  화면이었다)이 되고, 실제 연습은 `/learning/basic-conversation/<chapterId>/<level>`로
  한 단 더 들어간다. `data.js`에 `LEVEL_LABELS = { basic: "기본", intermediate: "중급",
  advanced: "심화" }`를 단일 소스로 두고, `index.js`가 `CHAPTERS`와 `LEVEL_LABELS`를
  곱해 챕터×단계 화면을 자동 생성한다 — 챕터가 늘어나도, 나중에 단계가 늘어나도 이 파일은
  고칠 필요가 없다. `renderChapter(chapter, level)`이 `chapter.sentences`를
  `(s.level || "basic") === level`로 필터링하고, 진행 상태 키도
  `state.learning[chapter.id]`에서 `state.learning[\`${chapter.id}-${level}\`]`로 바꿔
  단계별로 독립적으로 진행되게 했다(기본을 풀다 중급으로 갔다가 다시 기본으로 돌아와도
  기본 진행률이 유지된다). "목차로 돌아가기" 버튼은 최상위 목차가 아니라 그 챕터의 단계
  선택 화면으로 돌아가도록 문구도 "단계 다시 고르기"로 바꿨다 — 한 단계를 끝내고 바로
  다른 단계로 넘어가기 쉽게.
- **선택 2 — 콘텐츠는 30/12/6, 30/30/30 아님**: 사용자가 제안한 "기본 30·중급 30·심화
  30"을 그대로 다 채우지는 않았다. 기본은 챕터마다 24~26개였던 걸 4~6개씩 보태 30개
  안팎으로 채웠고(greeting 30, daily-routine 32, family-and-me 30, playground 30),
  기본과 심화 사이 난이도(간단한 질문·요청·감정 표현, 예 "How was your day?" · "Can I
  join you?")로 중급 문장을 챕터당 12개씩(총 48개) 새로 썼다. 심화는 이번엔 6개 그대로
  뒀다 — 심화 문장은 의견·이유·비교·협상이 들어간 더 복잡한 구조라, 세 단계를 한 번에
  30개씩(총 360문장) 채우면 검증 없이 양만 늘어나 품질이 떨어질 위험이 있다고 판단해
  범위를 좁혔다. 총 문장 수는 136 → 194(기본 122 + 중급 48 + 심화 24). 30/30/30을 다
  채우고 싶으면 이어서 요청하면 된다 — 특히 심화 확장이 남아 있다.
- **재사용**: 단계 선택 화면은 목차 화면(`renderBasicConversationIntro`)·심리테스트
  목록(`renderPsychList`)과 같은 `.test-list`/`.test-card` 카드 목록 패턴을 그대로 썼다.
  연습 화면의 레벨 배지도 기존 `.cover .tag` 클래스(D-72에서 "심화" 배지에 쓰던 것)를
  그대로 재사용해 `LEVEL_LABELS[level]`을 넣게 일반화했다 — 새 CSS 없이 됐다.
- **검증**: `node --test` 141/141(제네릭 테스트라 챕터/문장 id 중복 검사가 새 중급 문장·
  기본 추가 문장의 id도 자동으로 검사, 테스트 파일 무수정). 헤드리스 브라우저로 챕터
  클릭 시 단계 선택 화면(기본/중급/심화 카드, 각각 문장 개수 표시)이 뜨는지, 중급을
  고르면 `(1/12)`부터 시작해 그 단계 문장만 나오는지, 심화 배지가 뜨는지, 뒤로가기가
  단계 선택 화면으로 돌아가는지, 목차 화면 카드 설명이 "기본 N · 중급 M · 심화 K"로
  바뀌었는지 확인. 심화 6문장을 전부 건너뛰기로 완주해 완료 화면과 "단계 다시 고르기"
  버튼이 챕터의 단계 선택 화면으로 정확히 돌아가는지 확인.

### D-74. 기본/중급/심화를 챕터당 30개씩 완전히 채움
- **배경**: D-73에서 "30/30/30"을 제안받고도 기본 30·중급 12·심화 6으로 범위를 좁혀서
  올렸다 — 심화까지 한 번에 30개씩(총 360문장) 채우면 검증 없이 양만 늘어 품질이
  떨어질 위험이 있다고 판단해서였다. 사용자가 "덜 채운 것 마저 채워보자"고 이어서 요청 —
  D-73에서 스스로 남겨둔 격차를 마저 메우는 요청이라 새 구조 변경은 없다.
- **선택**: 중급을 챕터당 12개 → 30개로(+18×4=72), 심화를 챕터당 6개 → 30개로(+24×4=96)
  채웠다. 총 168문장 추가(194 → 362, 기본 122 + 중급 120 + 심화 120). 화면·라우팅·상태
  구조는 D-73 그대로 — `LEVEL_LABELS`로 필터링하는 방식이라 문장 개수만 늘어도 코드는
  하나도 안 고쳤다.
- **콘텐츠 방향**: 중급은 D-73에서 정한 톤(짧은 질문·요청, 예 "How do you feel now?" ·
  "Can you help me get dressed?")을 그대로 이어 챕터 소재 안에서 더 뽑았다. 심화는
  의견·이유·비교·협상·되묻기 패턴(D-72에서 정한 축)을 유지하되, 소재를 화해("Let's be
  friends again."), 공감("I understand how you feel."), 조건부 추론("I don't like
  vegetables, but I eat them anyway."), 협상("Can we agree on the rules first?")까지
  넓혀서 반복적으로 같은 패턴만 나오지 않게 했다.
- **검증**: `node -e`로 챕터별 기본/중급/심화 개수(전부 30/30/30, daily-routine만 기본
  32)와 챕터 안 문장 id 중복 여부(0건) 확인. `npm test` 141/141(제네릭 테스트라 문장
  168개 추가에도 테스트 파일 무수정). 헤드리스 브라우저로 목차 카드 설명이 "기본 30 ·
  중급 30 · 심화 30" 형태로 바뀌었는지, 단계 선택 화면의 각 카드가 "문장 30개"를
  보여주는지, family-and-me 심화 30문장을 전부 건너뛰기로 완주해 완료 문구("문장 30개를
  다 배웠어요!")가 나오는지 확인.

### D-77. 초등 영어회화(elementary-conversation) 신설 — 문법 진행·반복·produce 문장으로 "실질적 회화" 보강
- **배경**: 초등학생 버전 목차를 먼저 제안했더니(학년 3단계 × 챕터 4개, 학년별 상황
  주제) 사용자가 "실제로 저 카테고리대로 공부하면 언어 실력향상이 도움이 되게끔
  짜여져있다고 생각해?"라고 되물었다. 정직하게 답하면 아니었다 — ① 챕터를 상황으로만
  나눠서 문법이 어느 챕터에서 처음 나오고 다시 나오는지 추적이 없었고, ② 한 번 지나간
  챕터의 표현이 다시 나올 보장이 없어(recycling 없음) "본 적 있다"에서 끝날 위험이
  컸고, ③ 채점이 Levenshtein 유사도(정해진 문장을 얼마나 똑같이 따라했나)뿐이라
  발음·암기 훈련이지 새 문장을 만드는 능력은 안 봤다. 사용자가 "7세 이하는 반복이면
  되지만 초등학교부터는 실질적 회화 및 언어 향상이 동반되어야 한다"며 이 세 가지를
  보강해서 만들자고 확정했다.
- **선택 1 — 새 도구, 도구 안에 학년 트랙**: `docs/learning-architecture.md` §3-5가 이미
  "8~9세 전용 콘텐츠는 새 도구로 분리"를 권했던 것과, 이번에 사용자가 고른 옵션("초등
  전체를 한 도구 안에 학년 단계로")을 합쳐 `js/learning/elementary-conversation/`을
  새로 만들었다. 구조는 학년(GRADES) → 챕터(그 학년의 상황 목차) → 단계(기본/중급/심화,
  basic-conversation과 같은 개념) → 문장 연습 — 기존 챕터×단계 자동 생성(D-73)에 학년
  한 겹을 더 곱한 것뿐이라 새 개념을 만들지 않았다. 아직 안 만든 학년(중학년·고학년)은
  `GRADES` 배열에 아예 없다 — 이 저장소 관례(빈 기능을 화면에 먼저 노출하지 않는다)를
  지켰다.
- **선택 2 — 문법 진행(scope & sequence)**: 문장마다 `grammar`(그 학년의 `grammarPoints`
  배열 id, 예 `G1` be동사·`G2` 일반동사 현재형·`G3` 조동사 can·`G4` There is/are)를
  달았다. `test/learning.elementary.test.js`가 (a) 모든 문장의 grammar가 실재하는
  포인트를 가리키는지, (b) 등록만 해두고 아무 문장도 안 쓰는 죽은 포인트가 없는지를
  검사한다.
- **선택 3 — 반복(recycling) 규칙을 테스트로 강제**: "두 번째 챕터부터는 이전 챕터에서
  이미 나온 grammar를 최소 1문장 이상 재사용한다"를 `test/learning.elementary.test.js`에
  넣었다 — 새 챕터가 새 문법만 도입하고 끝나는 걸 코드로 막는다. 지금은 챕터가
  학년당 1개뿐이라 이 검사가 아직 트리거되진 않지만(2번째 챕터부터 적용), 챕터를
  늘릴 때부터 바로 지켜지게 미리 넣어뒀다. 콘텐츠 차원에서도 챕터 하나 안에서부터
  이미 지키고 있다 — 예를 들어 중급 문장 "What do you bring to school every day?"는
  기본 문장들이 쓴 G2(일반동사 현재형)를, 심화 문장 "I like school because I can see
  my friends."는 중급에서 나온 G3(can)를 다시 쓴다.
- **선택 4 — produce 문장으로 순수 반복의 천장을 깬다**: 문장에 `type: "produce"`를
  선택적으로 붙일 수 있게 했다. 이 타입은 정답 문장을 읽어주지 않고 **질문만 던진다**
  (`text`가 질문, `ko`가 그 번역) — 아이가 스스로 영어 문장을 만들어 답해야 한다.
  정답이 하나가 아니라 Levenshtein으로 채점할 수 없어서, 대신 `sample`(예시 답안
  1개 이상, `test/learning.elementary.test.js`가 강제)을 STT 결과 옆에 보여주고
  "잘 말했어요/다시 연습할래요" 자가평가로 넘어간다. 챕터 1개(학교 가는 날, 20문장)
  안에 produce 문장을 4개(중급 2·심화 2) 섞었다.
- **선택 5 — 약한 문장 재노출(SRS까지는 아니지만)**: "repeat" 문장에서 낮은 점수
  (retry)를 받거나 produce 문장을 "다시 연습할래요"로 자가평가하면 그 문장 id를
  `state.learning[key].weak`에 남긴다. 챕터를 다 풀면 완료 화면에 "헷갈렸던 문장만
  복습하기" 버튼이 뜨고, 그 목록만 다시 도는 연습 모드로 들어간다(같은 화면 안에서
  `sentences`/`N`/`reviewMode`를 바꿔 `showCard()`를 다시 부르는 방식 — 복습 모드는
  공유할 이유가 없는 일시적 상태라 새 주소를 만들지 않았다). 진짜 시간 간격을 둔
  SRS(며칠 뒤 다시 보여주기)는 아니다 — `docs/learning-architecture.md` §3-3에서
  이미 "로그인·영속 저장 인프라가 없다"로 미뤘던 이유가 D-68로 사라졌으니, 진짜 SRS는
  다음 단계로 남겨뒀다(아래 §3-3 갱신).
- **공용 로직 정리**: `score.js`(Levenshtein 유사도)와 TTS/STT 헬퍼(`speak`/`listen`/
  `supportsSpeech`/`supportsRecognition`)를 `js/learning/basic-conversation/`에서
  `js/learning/`(도구 폴더 밖, `cloud.js`와 같은 자리)로 옮겼다 — 두 번째 도구가
  생기면서 완전히 같은 로직을 복사하면 한쪽만 고치는 버그가 생길 자리였다. 새 파일
  `js/learning/speech.js`. basic-conversation의 import 경로만 바꿨고 동작은 그대로다.
- **범위**: 저학년(1~2학년) 챕터 1개(학교 가는 날, 기본 10·중급 6·심화 4, 총 20문장)만
  실제로 만들었다 — basic-conversation의 최종 목표(단계별 30개)보다 적게 시작해서,
  문법 태그·반복 규칙·produce·약한 문장 재노출이 실제로 동작하는 걸 먼저 확인하고
  같은 틀로 챕터·학년을 늘리기로 했다. 중학년·고학년, 저학년의 나머지 챕터 3개(교실
  에서·쉬는 시간·좋아하는 것)는 다음 단계.
- **검증**: `npm test` 146/146(새 파일 `test/learning.elementary.test.js` 5개 추가,
  기존 141개는 score.js/speech.js 이동 후에도 그대로 통과 — import 경로만 바뀌었다).

  → 챕터 카드(기본 10·중급 6·심화 4 표시) → 단계 카드 → 중급 진입 시 (1/6)부터 시작,
  일부러 오답을 말해 "한 번 더 따라해볼까요?" 피드백과 weak 표시 확인, 정답을 그대로
  말해 "완벽해요!" 확인, 건너뛰기로 2문장 통과, produce 문장에서 "질문" 태그·예시 답안
  2개 노출·자가평가(하나는 "다시 연습할래요"로 weak 표시, 하나는 "잘 말했어요") 확인,
  6문장 완주 후 "헷갈렸던 문장만 복습하기" 버튼이 뜨고 눌렀을 때 weak로 표시한 2문장만
  "(1/2)"로 다시 도는지 확인. 콘솔 에러 없음.
