# vocab-architecture — 9급 공무원 영단어 (civil-vocab)

> 선택 로드 문서. 어휘 학습 도구를 손볼 때만 읽는다. 학습 카테고리 공통 구조(도구 → 목차 →
> 챕터)는 `docs/learning-architecture.md`, 라우터 계약은 `docs/architecture.md`.

## 1. 배경 · 목표 (D-98)

사용자 요청: **9급 공무원 시험 대상 영어 어휘 학습 도구**. 연상암기법 + 효율적인 반복 암기,
로그인 계정별 진도 관리, **최종 목표 8000단어**.

계획 단계에서 사용자와 셋을 확정했다.
1. **복습은 분리** — 도구를 가로지르는 "오늘 복습"(D-92)에 어휘를 섞지 않는다.
2. **연상은 어원 우선** — 소리연상은 어원이 약한 단어에만.
3. **M1은 200단어 먼저** — 메커니즘을 먼저 확인하고 콘텐츠를 뒤에 붙인다(D-79에서 통한 방식).

목표가 8000단어라 **기존 학습 도구의 방식을 그대로 쓰면 깨지는 곳이 세 군데**였고, 그 셋이
이 문서의 뼈대다.

| 지점 | 기존 도구 | 8000단어에서 생기는 문제 | 이 도구의 선택 |
|------|-----------|--------------------------|-----------------|
| 데이터 로딩 | `data.js`를 `index.js`가 정적 import → 부팅에 전부 실림 | 단어 8000개 ≈ 수 MB가 첫 화면에서 다운로드 | **DAY 단위 파일 + 동적 import**(§2) |
| 진행률 저장 | `state.learning` 전체를 응답마다 통째로 업서트(`cloud.js`) | 카드 한 장 넘길 때마다 수백 KB 업로드 | **단어별 행을 갖는 별도 테이블**(§4, 아직 안 붙임) |
| 간격 반복 | `srs.js` Leitner `[0,1,3,7,16]`, 마지막 칸 넘기면 **삭제(졸업)** | 한 번 맞힌 단어가 영구히 사라져 장기 보존이 안 됨 | **별도 스케줄러**(§5, 아직 안 붙임) |

## 2. 데이터 구조 — 왜 DAY 파일로 쪼갰나

```
js/learning/civil-vocab/
  manifest.js      스테이지 · DAY 메타데이터(개수·제목·미리보기)만. 유일하게 정적 import된다
  roots.js         어원 사전(접두사 + 어근). 지금 156항목
  words/day-001.js 단어 50개. **동적 import로만** 불린다
  loader.js        DAY 캐시 로더 + 단어 id → DAY 계산
  session.js       문제지·빈칸 문제·오늘 큐 생성(순수 함수 — node --test 대상)
  srs.js           간격 반복 스케줄(순수 함수, SM-2 변형 — §5-1)
  screens.js       목차 화면 · DAY 학습 세션 · 오늘 복습 큐
  index.js         디스크립터(도구 카드 + 화면 배열)
```

- **manifest에 개수를 적어 둔다**: 목차 카드가 파일을 열지 않고도 "50단어"를 보여줘야 한다.
  실제 파일과 어긋날 수 있으므로 `test/learning.vocab.test.js`가 매번 대조한다.
- **단어 id가 곧 위치다**(`v003-17` = DAY 3의 17번째): "id → DAY" 색인을 따로 두면 그 색인이
  8000줄짜리 정적 로드 대상이 돼서 동적 import의 의미가 사라진다.
- **로더는 매니페스트에 있는 id만 허용한다**: id를 그대로 경로에 붙이는 함수라, 검증이 없으면
  화면·주소에서 흘러들어온 문자열이 경로가 된다.
- **정적 import 금지를 테스트로 강제한다**: 주석으로만 두면 다음 세션이 무심코 깬다.
  `words/day-*.js`를 정적 import하는 파일이 있으면 `npm test`가 실패한다.

## 3. 연상암기법 — 어원 우선 (사용자 지시)

단어마다 연상을 하나씩 지으면 8000개를 각각 외워야 한다. 어근은 되풀이되므로(`tain` 하나로
attain·maintain·obtain·pertain·retain···) **어원 사전 + 단어별 한 줄 힌트**로 나눴다 —
저작량과 학습량이 같이 줄고, 처음 보는 단어도 쪼개서 짐작할 수 있다.

```js
{ id: "v001-01", word: "abolish", pos: "v.", ko: ["폐지하다", "없애다"], freq: 1,
  roots: ["ab", "ol"], hint: "ab(떨어져) + ol(자라다) → 자라 있던 제도를 뿌리째 떼어내다",
  ex: { en: "…", ko: "…" }, syn: ["repeal", "eliminate"] }
```

- **억지 어원을 붙이지 않는다**: 어원이 뚜렷하지 않은 단어(`boost` 등)는 `roots`를 비우고
  `sound`(소리연상)를 쓴다. D-94에서 정한 "억지 데이터는 신호가 없는 것보다 나쁘다"와 같은 판단.
  대신 **둘 다 없는 단어는 금지**다(테스트가 잡는다) — 그러면 "그냥 외워라"가 되어 이 도구의
  존재 이유가 사라진다.
- **죽은 어근 금지**: 사전에만 있고 아무 단어도 안 쓰는 항목은 테스트가 잡는다
  (elementary-conversation의 `grammarPoints` 규칙과 같다).
- **저작권**: 표제어와 기본 뜻은 사실 정보지만 **예문·연상·배열 순서는 창작물**이다. 시판
  어휘집을 옮기지 않고 직접 쓴다. 이 원칙은 콘텐츠를 8000개까지 늘리는 동안 계속 유효하다.
- **freq(빈출 등급 1~5)**: DAY 배치의 단일 소스. 목표가 8000이어도 **앞쪽 2000단어가 시험의
  대부분을 덮도록** 배치해서, 중간에 멈춰도 손해가 없게 한다(9급 실전에 실제로 필요한 어휘는
  통상 3000~4500으로 본다 — 8000은 사용자가 정한 최종 목표이고, 순서로 그 위험을 상쇄한다).

## 4. 진행 상태 — 지금과 나중

**지금(M1)**: `state.vocab.days[dayId] = { index, best, wrong }` — 세션 한정 메모리.
`state.learning`에 얹지 않았다: 그쪽은 통째로 한 행에 업서트되는 구조라(`js/learning/cloud.js`)
8000단어를 섞으면 카드 한 장마다 수백 KB를 올리게 된다.

**나중(M3, 계정별 저장)**: `vocab_progress` 테이블 — `(user_id, word_id)` PK,
`due / interval / ease / reps / lapses`, RLS로 본인 행만, `(user_id, due)` 인덱스.
응답 1건이 100B 남짓이고 "오늘 볼 것"은 `where due <= now()`로 **서버가 고른다**(8000개를
클라이언트로 안 내린다). 세션 중에는 메모리에 쌓아 배치 업서트하고 화면 이탈 시 flush.
⚠️ 이때 **영속 데이터가 하나 더 생기므로** `CLAUDE.md`의 "영속 데이터" 항목과 `/privacy`를
같은 커밋에서 갱신한다(부부 체크 코드·학습 진행률 때와 같은 절차).

## 5. 아직 안 붙인 것 — 붙일 때 이렇게

### 5-1. 간격 반복(SRS) — D-99로 붙임
- `js/learning/srs.js`를 **재사용하지 않았다**: 그 스케줄은 "틀린 문장 몇 개"를 위한 것이라
  마지막 칸을 넘기면 목록에서 지운다(졸업). 8000단어 장기 보존에서는 한 번 맞힌 단어가
  영구히 사라지는 규칙이 된다. 그래서 `js/learning/civil-vocab/srs.js`를 따로 뒀다 —
  **도구 안에 둔 이유**는 이 스케줄을 쓰는 게 어휘 카드뿐이어서다(문장 도구가 같이 쓰기
  시작하면 그때 `js/learning/`으로 올린다. score.js가 걸어온 길과 같다).
- 규칙: ease 2.5 시작 · 1.3 하한, 처음 두 번은 고정(1일 → 3일), 그 뒤 `간격 × ease`
  (1 → 3 → 8 → 20 → 50 → 125일), 상한 365일. 틀리면 간격 0 + ease −0.2 + lapses++,
  **졸업(삭제)은 없다**. `hard`는 규칙만 만들어 뒀고 화면 버튼은 아직 없다(3단계 평가를 붙일
  자리) — 쓰이지 않는 분기가 아니라 스케줄의 일부라 테스트가 직접 검증한다.
- **하루 신규 상한**(`DEFAULT_NEW_PER_DAY = 20`, manifest.js): 상한이 없으면 신규만 몰아서
  하다가 며칠 뒤 복습이 눈덩이가 된다. 8000단어에서 이 값이 사실상 코스의 속도다.
- 큐는 `/learning/civil-vocab/today`가 돈다: 복습(due) + 신규를 섞고(`buildDailyQueue`),
  틀린 항목은 같은 세션에 다시 넣되 **두 번까지만** 되돌린다(무한히 되돌리면 "남은 개수"가
  줄지 않는 화면이 된다 — 오늘 못 외운 단어는 어차피 내일 일정에 올라 있다).
- 인출 강도는 단계적으로 오른다(`retrievalMode`): 만난 지 얼마 안 된 단어는 뜻 고르기(재인),
  `reps >= 2`부터 빈칸 채우기(산출).
- **한계**: 진행이 아직 세션 메모리라 새로고침하면 일정이 날아간다. 이건 M3(계정별 저장)에서
  풀린다 — `state.vocab.cards[wordId]`의 모양이 그대로 `vocab_progress` 한 행이 되도록 맞춰뒀다.

### 5-2. 복습 진입로 (분리 결정) — 화면은 D-99로 붙음
- 이 도구는 `resolveReview`를 **일부러 두지 않는다**. 도구를 가로지르는 "오늘 복습"(D-92)은
  문장 카드 UI이고, 하루 수십~수백 개가 나오는 단어와 섞이면 그 화면이 단어로 덮인다.
- 대신 어휘 복습은 이 도구 안의 `/learning/civil-vocab/today`에 뒀다(D-99). 도구 인트로 맨
  위에 "오늘 복습 + 새 단어" 카드가 항상 있고 남은 개수를 보여준다. 학습 목록·마이페이지에
  "단어 N개"를 노출하는 건 아직 안 했다 — 그 화면들은 `state.learning`만 집계하므로,
  §5-3의 `summary()` 훅과 같이 붙이는 게 맞다.

### 5-3. 마이페이지 집계
- 홈·마이페이지는 학습 도구를 import하지 않는다(D-70). 어휘 진행은 `state.learning`이 아니라
  `state.vocab`에 있으므로, 도구 디스크립터에 선택적 `summary()` 훅을 추가해 수치만 돌려받는
  방식으로 붙인다(화면이 도구를 몰라도 된다는 경계는 그대로).

### 5-4. 학습 모드 — 두 가지가 D-99로 붙음
- 지금은 ①단어 카드(뜻·어원 **지연 노출**) ②뜻 고르기(4지선다) ③**빈칸 채우기**(예문에서
  표제어를 지운 산출 문제) 셋이다.
- **지연 노출**: 카드 앞면은 단어+품사만, "뜻 확인하기"를 눌러야 뜻·어원·예문이 열리고
  거기서 😅 헷갈려요 / 👍 알겠어요로 스스로 평가한다. 정답과 어원을 같이 깔아두면 읽고
  나서 "안다"고 느끼지만 떠올려본 적은 없다(유창성 착각). 강제하지 않고 토글로 끌 수 있다
  (D-61·D-93과 같은 판단) — 설정은 `state.vocab.prefs.recall`(세션 한정 표시 설정이라
  진행률과 섞지 않는다).
- **빈칸 채우기**: `makeCloze()`가 예문에서 표제어(굴절형 포함)를 찾아 지운다. **콘텐츠를
  새로 만들지 않는다** — "예문에 표제어가 들어 있다"를 테스트가 이미 보장해서 성립하는
  방식이다. 채점은 예문 형태와 표제어 형태를 둘 다 받아주고(철자 연습이지 굴절 시험이 아니다),
  힌트로 첫 글자와 길이만 준다. 같은 단어가 두 번 나오는 예문은 두 자리 모두 지운다.
- 다음 후보: 듣고 뜻 고르기(TTS는 이미 붙어 있다), 유의어 고르기(syn 필드가 이미 있다).
  **오답 보기는 계속 같은 DAY에서 자동 생성**한다 — 보기를 저작하지 않으므로 단어가 늘면
  문제도 저절로 는다(D-95에서 쓴 방식).

## 6. 화면 흐름

```
/learning                      학습 목록(도구 카드)
/learning/civil-vocab          오늘 할 공부 + 스테이지 → DAY 목록 (진행·최고 정답률 표시)
/learning/civil-vocab/today    오늘 큐 — 복습(due) + 새 단어를 섞어 한 줄로 돈다 (D-99)
/learning/civil-vocab/day-001  단어 카드 → 확인 문제 → 빈칸 채우기 (한 화면 안에서 in-place 전환)
```

- **DAY 화면과 오늘 큐의 역할이 다르다**: DAY는 "처음 훑는 곳"이고, 기억에 남기는 일은 날짜를
  두고 다시 만나는 오늘 큐에서 일어난다. 두 화면의 모든 응답이 같은 `state.vocab.cards`
  일정으로 들어간다.

- 라우터의 `render()`는 동기 함수라, DAY 화면은 **골격을 먼저 그리고** `loadDay()`가 끝나면
  카드 자리만 채운다. 로딩 중 이탈에 대비해 `onLeave`에서 플래그를 세우고 늦게 온 응답을
  버린다 — 안 그러면 다른 화면 위에 단어 카드를 그린다(`docs/ERRORS.md` E-4와 같은 종류).
- 결과 화면의 "틀린 단어만 다시 보기"는 라우터를 타지 않는다(공유할 이유가 없는 일시적 모드) —
  elementary의 "헷갈렸던 문장만 복습하기"와 같은 판단.

| P1 | 800 | 최빈출 |

확장은 **`words/day-NNN.js` 추가 + `manifest.js`에 줄 하나**가 전부다 — 화면·라우팅·테스트는
안 고친다. 한 번에 몰아서 만들지 않는 이유는 D-73/74에서 겪은 "검증 없이 양만 늘리면 품질이
떨어진다"이다.
