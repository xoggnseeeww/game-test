# VERIFY_PENDING — 배포 후 확인 필요 목록

> 선택 로드 문서. **샌드박스에서 확인하지 못한 것**만 모은다 — "확인됨"으로 간주하지 말 것.
> `CLAUDE.md`의 절대 규칙("확인하지 못한 항목은 여기로 옮긴다")이 가리키는 파일이다.
> 원래 `CURRENT_TASK.md` 안에 있었는데, 그 파일이 매 세션 자동 로드라 80줄짜리 미확인 목록이
> 계속 토큰을 먹고 있어서 분리했다(D-105).

**왜 확인이 안 되나**: 이 샌드박스는 아웃바운드가 프록시로 막혀 있다. 그래서 ①외부 CDN
(카카오 AdFit `t1.daumcdn.net`, Supabase JS `esm.sh`, 웹폰트) ②실제 배포본 접속
③실기기 하드웨어(마이크·오디오·터치) 셋은 **원리적으로 여기서 확인할 수 없다.**
아래 항목은 전부 이 셋 중 하나에 걸린 것이다.

## ⚠️ 조치가 필요한 것 (코드로는 못 고침)

- **일반 방문자 로그인이 실기기에서 안 됨(D-71)** — 로그인 버튼 → 계정 선택까지는 되지만 앱은
  로그인 안 된 상태로 남는다. Supabase `get_logs(auth)`상 서버 쪽은 매번 성공으로 기록돼
  있어(에러 없음) 클라이언트 버그가 아니라, **Supabase 대시보드 → Authentication → URL
  Configuration → Redirect URLs에 `https://fun.data-pantry.com/`이 없어** GoTrue가 조용히
  Site URL로 되돌리는 것으로 진단(근거·진단법 `docs/ERRORS.md` E-12).
  **사용자가 대시보드에서 추가해야 한다.** 추가 후 확인: 로그인 → 홈 리다이렉트 → 햄버거에
  점 배지(D-70), 메뉴에 이름·로그아웃(D-71), 관리자면 부부 체크 "출시 예정" 배지 사라짐.

## 계정·저장 (로그인이 풀려야 확인 가능 — 위 항목과 묶임)

- **계정 전환 시 데이터 격리(D-104)** — 계정 A 로그인 → 학습 → 로그아웃 → 계정 B 로그인 →
  마이페이지·어휘 인트로가 **B 자신의 진행만** 보여주는지(A의 흔적이 안 남는지). 가짜 cloud를
  주입한 순수 로직 테스트로는 통과했지만 실제 Supabase 왕복은 재현 못 했다.
- **어휘 일정 계정 저장 왕복(D-100)** — 로그인 → 단어 몇 개 → 새로고침 → 진행 유지되는지.
  Supabase 대시보드에서 `vocab_progress` 행이 실제로 쌓이는지.
- **하루 목표 저장(D-102)** — 목표를 바꾼 뒤 로그아웃→로그인 시 그 값이 유지되는지
  (`vocab_settings`).
- **학습 진행률 동기화 왕복(D-68)** — 로그인 후 문장 진행 → 새로고침 시 이어지는지, 다른
  기기에서 같은 계정으로 진행률이 따라오는지. ⚠️ 이건 D-100 전까지 **테이블 GRANT 누락으로
  한 번도 저장된 적이 없었다**(E-16) — 그 수정 후 실제로 쌓이는지 함께 확인.
- **마이페이지(D-70)** — CDN이 실제로 붙었을 때 로그인 버튼이 정상 렌더되는지(샌드박스는
  "불러오지 못했어요" 폴백만 확인됨), 학습 진행 집계가 실제와 맞는지.

## 어휘 도구 (D-98~D-103)

- **DAY 파일 동적 import** — 배포본에서 DAY 진입 한 번. 다른 js와 같은 정적 자산 경로라 새
  위험은 없지만 실제로 눌러본 적이 없다(경로가 틀리면 `_redirects` SPA 폴백 때문에 404가
  아니라 index.html이 와서 문법 에러로 터진다).
- **빈칸 채우기 모바일 키보드** — 첫 글자 대문자 변환·자동교정이 실제로 꺼지는지
  (`autocapitalize="none"` 등을 넣었지만 실기기 확인 필요).
- **SRS 간격이 실제로 "내일"인지(D-103)** — 오늘 학습한 단어가 다음 날 실제로 다시 올라오는지.
  값 자체는 헤드리스로 검증했지만 날짜가 바뀐 뒤의 동작은 시간이 지나야 볼 수 있다.
- **어휘·예문 자연스러움 전수 검토** — 아직 안 했다(D-85가 문장 도구에 한 것과 같은 작업).

## 음성·오디오 (하드웨어 필요)

- **학습 카테고리 음성 인식·재생(D-60)** — 헤드리스는 마이크가 없어 가짜 `SpeechRecognition`으로
  판정 로직만 확인했다. 실기기에서 마이크 권한, 실제 인식 정확도, 0.75배속 음질 확인 필요.
- **TTS 발음(D-97)** — 실기기에서 실제로 정상인지. 기기에 영어 음성이 아예 없으면 코드로
  못 고친다(그땐 `pickVoice`가 null을 주고 브라우저 기본에 맡긴다).
- **iOS 녹음 폴백(D-95)** — 아이폰에서 마이크 권한 → 녹음 → 재생이 도는지. 헤드리스는 가짜
  오디오 장치라 iOS 권한 흐름·오디오 포맷(mp4/aac)을 재현 못 한다.
- **NumPath Web Audio** — iOS Safari의 첫 제스처 전 `AudioContext` suspended 상태에서 타일
  클릭으로 정말 resume되는지, 무음 스위치일 때 거슬리지 않는지.

## 공유·OG·폰트 (외부 크롤러·CDN 필요)

- **OG 미리보기 실제 렌더링** — 카카오톡/트위터/페이스북 디버거로 확인 필요. 카카오는
  `https://developers.kakao.com/tool/clear/og`로 각 URL을 제출해야 캐시가 갱신된다.
- **`og-*.png` 폰트** — 생성 시엔 웹폰트를 직접 불러와 그렸지만, 크롤러가 리사이즈·재인코딩하며
  글자가 깨지는 사례가 있어 확인 필요.
- **결과 카드·짧은 코드 카드 폰트** — CDN 차단으로 sans-serif/monospace 폴백으로만 그려졌다.
- **`navigator.share` 공유시트** — 헤드리스엔 API가 없어 클립보드 폴백만 확인됨.
- **데이터팬트리 헤더 FUN 버튼** — 두 사이트가 각각 배포된 뒤 상호 이동 확인 필요.

## 인프라·레이아웃

- **`_redirects` 실동작** — 로컬은 `serve.py`로 흉내 낸 것. 배포본에서
  `/test/disc/result/lion` 직접 접속이 200인지.
- **부부 결과 매칭 KV 바인딩 실배포** — Cloudflare Pages가 `wrangler.jsonc`의 KV 바인딩을
  git 연동 배포에서 자동으로 읽는지는 배포해봐야 안다. 안 읽히면 Pages → Settings →
  Bindings에서 `COUPLE_CODES`를 수동으로 한 번 추가해야 한다. 확인법: 초대 화면에서 짧은
  코드가 "발급 중..."에서 실제 코드로 바뀌는지.
- **KV 쓰기 한도(1,000회/일) 소진 여부** — 소진 시 폴백 문구로 넘어가게 해뒀지만, 실제 발생
  여부는 Cloudflare 대시보드 KV 사용량으로만 확인 가능.
- **우상단 햄버거 버튼 위치(D-57)** — `top` 값이 두 행(`.header`/`.back-row`) 높이 차이를
  계산으로 잡은 근사치다. 다양한 기기·가로 모드, 진한 결과 카드 위에서 잘 보이는지.
- **홈 화면 헤더 레이아웃** — ☰ 제거 후 로고만 남은 좌측 정렬이 배포본에서도 안 깨지는지.
- **5×5 보드 터치 히트 영역** — NumPath 고레벨 타일이 손가락으로 누르기에 충분한지.

## 사람 판단이 필요한 것

- **개인정보처리방침(`/privacy`) 검토** — 코드가 실제로 처리하는 것만 적었지만 법률 자문이
  아니다. 상용 운영하려면 사업자등록·통신판매업 신고 여부와 함께 사람이 한 번 더 볼 것.
- **부부 체크 49문항 이탈률** — 약 6분 30초로 다른 검사(1분)보다 훨씬 길다. 홈 문구는 여전히
  "1분이면 끝나는"이다. 실제 이탈 지점을 Cloudflare Web Analytics 경로별 필터로 확인 필요.
- **부부 체크 배우자 초대 링크 전달** — 카카오톡으로 `?p=<코드>` 링크를 보냈을 때 끝이 잘리지
  않는지. 잘린 코드는 체크섬에 걸려 직접 입력 폼으로 넘어가지만(D-45), "실제로 잘리는지"는
  확인 못 했다. 짧은 코드(8자)를 따로 보내면 우회된다.
