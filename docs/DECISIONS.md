### D-1. [초기] 결과 유형을 총점이 아니라 축별 프로필로
- **선택**: 집중/충동/에너지 3개 축 각각의 "높음/낮음"을 조합해 유형을 정한다(`profileKey()`).
- **이유**: 총점 합산이면 한 축만 극단적으로 높아도 나머지 두 축에 묻혀 "평범"으로 나온다. DSM-5가 부주의 우세형 / 과잉행동-충동 우세형 / 복합형으로 나누는 축과 동일하다.
- **기각**: 총점 구간별 등급(경미/중등도/심함) — 등급 표현이 진단처럼 읽히는 문제까지 겹쳤다.

### D-2. [초기] 유형을 8종(축당 고/저 2단계)으로 고정
- **선택**: 축당 2단계 × 3축 = 8종. 대신 유형 **안에서** `axisIntensityText()`가 퍼센트 구간별로 다른 문장을 준다.
- **이유**: 문항이 축당 4개뿐이라 3단계로 쪼개면 경계가 얇아져 근거가 약해진다. 같은 "충동 우세"라도 63%와 97%가 다른 문장을 받으면 유형 수를 늘리지 않고도 해상도가 올라간다.
- **기각**: 축당 3단계(27종) — 유형별 문구 27벌을 유지할 수 없고, 경계 1~2점 차이로 유형이 뒤집힌다.

### D-3. [초기] 문항을 임상 척도(ASRS 등) 그대로 쓰지 않고 자체 재구성
- **선택**: DSM-5가 다루는 증상 영역만 참고해 자체 문항 12개 작성. 축당 3문항 정방향 + 1문항 역채점.
- **이유**: ① 임상 척도를 그대로 옮기면 저작권·오용 문제가 생긴다 ② 역채점 문항이 없으면 "다 그렇다"로 답할 때 점수가 한쪽으로만 쏠린다.
- **연결 규칙**: `CLAUDE.md`의 "의학적 진단 표현 금지" — `disclaimer` 문구는 이 결정의 필수 짝이다. 제거하면 안 된다.

### D-4. 반응속도 게임을 미니게임이 아니라 테스트 하위 경로로
- **선택**: `/game/reaction`이 아니라 `/test/adhd/reaction/*`.
- **이유**: 게임 결과가 독립 콘텐츠가 아니라 테스트 점수에 반영되는 보너스다. 경로가 소속을 드러내야 사용자가 "왜 이걸 하는지"를 안다.
- **부작용**: `/game`이 빈 목록이 됐다 — `CURRENT_TASK.md` 다음 작업 1번.
- **갱신(D-19)**: "보너스"였던 부분은 이후 **필수 마지막 단계**로 바뀌었다. 이 결정(경로 소속)은 그대로 유효하다.

### D-5. 게임 보너스를 "반응 속도"가 아니라 오류 종류로
- **선택**: 억제 실패(commission) + 성급한 반응(premature) → 충동 / 누락(omission) + 반응시간 변산성(rtSD) → 집중.
- **이유**: Go/No-Go·CPT 계열 과제에서 실제로 쓰는 두 축을 그대로 옮긴 것.
- **되돌림**: 초기에는 **"빨리 누를수록 충동적"** 규칙을 썼다가 폐기했다. 반사신경과 충동성을 혼동한 것이라, 반응이 빠른 사람이 무조건 충동적으로 나왔다.
  → **이 규칙을 다시 제안하지 말 것.**
- **구현 메모**: 충동은 commission과 premature 중 **더 높은 쪽을 채택**한다(`Math.max`). 둘은 같은 구성개념의 다른 신호라 더하면 이중 계산이 된다.

### D-6. 에너지 축에는 게임 보너스를 넣지 않음
- **선택**: `gameBonuses()`는 `impulse`와 `focus`만 반환한다.
- **이유**: 과잉행동(에너지)을 Go/No-Go로 측정할 근거가 없다. 없는 근거로 숫자를 만들면 결과 전체의 신뢰가 깎인다.
- **기각**: "라운드 간 대기 중 화면 터치 횟수"를 과잉행동 지표로 쓰기 — 측정하는 게 조바심인지 습관인지 구분할 수 없다.

### D-7. 공유 URL을 결과별 슬러그 주소로
- **선택**: `${origin}/test/adhd/result/<slug>` (`SLUG_TO_PROFILE` 8종).
- **이유**: 친구가 링크를 열면 "내 결과"를 봐야 공유가 성립한다.
- **되돌림**: 처음엔 페이지 자체 주소(`/test/adhd/result`, 모두에게 동일)를 복사했다. 친구가 열면 **빈 테스트 화면**만 나왔고, 공유 버튼이 작동하는 것처럼 보여서 아무도 눈치채지 못했다.
- **연결 규칙**: `RESULT_TYPES`에 키를 추가하면 `SLUG_TO_PROFILE`도 추가해야 한다(`CLAUDE.md` 동기화 매트릭스). 빠뜨리면 공유 URL이 **조용히** 홈으로 폴백한다.

### D-8. 카카오 SDK 대신 `navigator.share`
- **선택**: `navigator.share` → 미지원 시 클립보드 복사 폴백.
- **이유**: 모바일 브라우저의 네이티브 공유시트에 이미 카카오톡이 들어 있다. 전용 SDK를 붙이면 앱 키 발급·도메인 등록·외부 스크립트 로드가 전부 따라온다. 의존성 0이라는 이 프로젝트의 성격과 맞지 않는다.
- **기각**: Kakao JS SDK — 위 비용 대비 이득이 데스크톱 폴백 하나뿐이었다.

### D-9. 빌드 도구·프레임워크를 도입하지 않음 *(2026-07 갱신)*
- **선택**: 번들러·프레임워크 없이 **브라우저 네이티브 ES 모듈**. `package.json`은 있지만 `"scripts": { "test": "node --test" }`뿐이고 **런타임 의존성은 0**이다.
- **이유**: 빌드 파이프라인이 없으면 "소스에 썼는데 산출물에 안 실렸다"는 계층 착오가 구조적으로 발생할 수 없다. 배포는 파일을 그대로 올리는 것이 전부다.
- **갱신 내역**: 초기엔 단일 `app.js`였다. 파일이 커지고 테스트가 둘로 늘면서 `js/` 모듈 트리로 쪼갰다 — **빌드는 여전히 없다.** 모듈 분리는 번들러 없이 가능하다.
- **대가**: `import` 경로에 확장자 `.js`가 필수이고, 파일 수만큼 요청이 늘어난다. 화면 20개 규모에서는 문제되지 않는다.
- **트레이드오프(인지하고 선택)**: 타입 체크·린트가 없다 → 템플릿 문자열 안의 클래스명 오타는 아무도 못 잡는다. `test/modules.test.js`(import/export 정합성)와 `scripts/verify.cjs`(브라우저)가 이 구멍을 메운다.
- **파생 결정**: 회귀 스위트(`scripts/verify.cjs`)는 playwright가 필요하지만 **레포 의존성으로 넣지 않는다.** `NODE_PATH`로 레포 밖 설치본을 참조한다 — 검증 도구 하나 때문에 "런타임 의존성 0"이라는 성격을 잃지 않는다.
  확장자가 `.cjs`인 이유: `"type": "module"` 때문에 `.js`는 ESM으로 읽히고, **ESM은 `NODE_PATH`를 무시**해서 외부 설치본을 못 찾는다.
- **재검토 조건**: 화면이 20개를 넘거나 한 모듈이 800줄을 넘으면 다시 판단한다.

### D-10. ADHD 명칭 유지 (리브랜딩 되돌림)
- **되돌림**: "ADHD"를 빼고 일반적인 집중력/산만함 테스트로 리브랜딩했다가 **전체를 되돌렸다**(커밋 `3f4aa6b` → `8930f3d`).
- **이유**: 명칭을 빼니 이 테스트가 무엇을 재는지 사용자가 알 수 없어졌고, 검색 유입 근거도 함께 사라졌다.
- **대신 채택한 방향**: 명칭은 유지하되 **문구를 임상적으로 들리지 않게 다듬고**(`58155eb`) `disclaimer`로 진단이 아님을 명시한다.
- → **이 리브랜딩을 다시 제안하지 말 것.** 우려가 있다면 명칭이 아니라 문구를 손본다.

### D-11. `:has()` 대신 JS 클래스 토글
- **선택**: `app.classList.toggle("has-bottom-nav", ...)`를 JS로 직접 건다.
- **이유**: CSS `:has()`를 쓰면 지원하지 않는 브라우저에서 하단 네비게이션 여백이 사라져 콘텐츠가 가려진다. 정적 사이트라 폴리필도 없다.
- **기각**: `:has()` + `@supports` 폴백 — 규칙이 두 벌이 되고 어느 쪽이 도는지 확인이 어렵다.

### D-12. `SessionStart` 훅을 만들지 않음
- **선택**: `.claude/settings.json`에 훅을 등록하지 않는다.
- **이유**: 설치할 의존성도, 실행할 빌드도 없다. 훅이 할 일이 없는데 만들면 유지 대상만 늘어난다.
- **재검토 조건**: 의존성이나 빌드 단계가 생기는 순간 즉시 추가한다. 그때 **`git reset --hard` 류는 `startup`/`clear` source에서만** 돌게 할 것 — `resume`/`compact`에서 돌면 진행 중이던 작업이 통째로 날아간다.

### D-13. 라우터를 레지스트리 방식으로 (5곳 → 1곳)
- **선택**: 화면 하나 = 디스크립터 객체 하나(`{ id, path, title, render, theme?, guard?, dynamicPath? }`). 라우터는 등록된 것만 안다.
- **이유**: 예전엔 화면을 추가하려면 `ROUTES`·`SCREEN_TO_PATH`·`SCREEN_TITLES`·`render()` switch·`resolveScreen()`의 if문까지 **5곳**을 고쳐야 했다.
  테스트가 둘로 늘면서 빠뜨릴 확률이 그만큼 곱해졌다. **결합을 문서(동기화 매트릭스)로 관리하는 대신 없앴다.**
- **부수 효과**: `SCREEN_TO_PATH`가 `ROUTES`를 뒤집는 방식이라 **두 주소가 같은 화면을 가리키면 뒤에 온 쪽이 조용히 이겼다.**
  지금은 경로가 중복되면 등록 시점에 throw 한다 — 조용한 실패를 시끄러운 실패로 바꿨다. `test/modules.test.js`가 이를 검사한다.
- **문서 영향**: `CLAUDE.md`의 "새 화면 = 4곳 동시 수정" 규칙은 이 결정으로 **폐기**됐다. 결합이 사라지면 매트릭스 항목도 지운다.

### D-14. 정리 대상을 이름이 아니라 등록으로 (`onLeave`)
- **선택**: 화면이 스스로 `onLeave(fn)`으로 정리 방법을 등록하고, `setScreen()`이 전환 직전에 전부 실행한다.
- **이유**: 예전엔 `setScreen()`이 반응속도 게임의 `setTimeout` **하나만** 이름으로 알고 `clearTimeout` 했다.
  `requestAnimationFrame` 콜백은 그 방식으로 못 막아서, **게임 도중 뒤로가기를 하면 살아남은 콜백이 다른 화면을 결과 화면으로 밀어버렸다.**
- **기각**: `rAF` 핸들도 모듈 스코프 변수로 하나 더 두기 — 정리 대상이 늘 때마다 같은 실수가 반복된다. 종류를 하나 늘리는 게 아니라 **구조를 바꿔야** 끝난다.
- **일반 원칙**: 정확도를 높이는 것보다 **빠뜨릴 수 없는 구조**가 회귀를 끝낸다.

### D-15. DISC를 강제선택(ipsative) 방식으로
- **선택**: 상황마다 선택지 4개 중 "가장 나 같은 것"과 "가장 아닌 것"을 고른다. 축별 원점수의 합은 **항상 0**.
- **이유**: 각 축을 독립 척도로 물으면 "다 그렇다"로 답할 때 전 축이 함께 올라가 유형이 안 갈린다. 강제선택은 상대적 우위만 남긴다.
- **대가(인지하고 선택)**: 결과는 **개인 내 상대값**이라 사람 간 절대 비교에 쓸 수 없다. 결과 문구도 그 전제로 쓴다.
- **불변식은 테스트로 고정**: 합 0 / 응답 순서 무관 / 동점 시 결정론 / **대척점 조합(DS·SD·IC·CI)은 어떤 입력에도 안 나옴** / 12유형 전부 도달 가능 → `test/disc.score.test.js`

### D-16. 화면 id에 옛 이름(`test-*`)을 유지
- **선택**: ADHD 화면 id를 `adhd-*`로 개명하지 않고 `test-intro`·`test-result` 그대로 둔다.
- **이유**: id는 `history.state`에 저장된다. 배포 전에 열어둔 탭에는 옛 id가 남아 있어, 개명하면 **배포 직후 그 탭들의 뒤로가기가 깨진다.**
- **기각**: DISC와 이름 규칙을 맞추는 리팩터링 — 일관성보다 이미 열려 있는 세션이 우선이다.
- **방어**: `resolveScreen()`이 미등록 id를 만나면 주소 기준으로 폴백한다(예전엔 switch가 그냥 빠져나가 빈 화면이 됐다). → `docs/ERRORS.md` E-2b

### D-17. 개수 하드코딩 금지를 문서 규칙에서 테스트로 승격
- **선택**: `test/copy.test.js`가 화면 문구 속 리터럴 개수를 검사해 실패시킨다.
- **이유**: 같은 실수가 **3회** 났다(ADHD 목록 카드 / Go/No-Go 주석 / DISC 인트로 본문). 2회에서 문서화, 3회에서 코드 강제 — 재발 횟수가 계층을 정한다.
- **구현 메모**: 첫 정규식은 `문항|가지|라운드`만 봐서 `상황 12개`를 놓쳤다(단위가 숫자 뒤에 오는 조사형). **검사를 추가하면 버그를 일부러 되살려 빨간불을 확인할 것** — 초록불만 보면 검사가 비어 있어도 모른다.

### D-18. 딜레마 게임을 결과 화면의 선택적 보너스에서 문항 뒤의 강제 단계로
- **선택**: 문항 12개를 마치면 결과가 아니라 곧바로 `dilemma-intro`로 넘어간다. 게임까지 마쳐야 `disc-result`의 guard를 통과한다. 별도의 "게임 결과" 화면(`dilemma-result`)은 없앴다 — 게임이 끝나면 `dilemma-play`가 `state.disc.dilemma`를 채우고 바로 `disc-result`로 이동해, 게임 신호까지 반영된 유형을 한 번에 보여준다.
- **이유**: 원래는 결과 화면에서 "다음 콘텐츠"로 선택적으로 들어가는 보너스였다. 그러면 문항만 풀고 게임은 안 하는 사람이 대다수가 되어, 딜레마 게임이 존재하는 이유(속도·우선순위 신호를 결과에 반영하는 것)가 대부분의 사용자에게 무의미해진다.
- **대가(인지하고 선택)**: 완주까지 필요한 상호작용이 늘어난다(문항 24탭 + 게임 8라운드). `disc-intro`의 세 번째 meta-chip(`+N라운드`)으로 시작 전에 미리 알려서, 24탭을 끝낸 뒤에야 게임이 있다는 걸 알게 되는 상황은 피했다.
- **뒤로가기 처리**: `disc-result`가 더 이상 이전 화면이 될 수 없으므로(게임이 안 끝났으면 guard가 다시 게임으로 돌려보낸다), `dilemma-intro`의 뒤로가기는 `disc-question`으로 간다 — 그 화면의 기존 guard가 "답이 다 차 있으면 마지막 문항으로 되돌림"을 이미 하고 있어서 새 상태 없이 재사용된다. `dilemma-play`의 뒤로가기는 `dilemma-intro`로 돌아가 게임만 다시 시작한다(문항 답변은 유지).
- **기각**: 게임을 결과 화면 위쪽(문항 직후)에 계속 두되 "필수"라고 안내만 하는 방식 — 사용자가 안내를 건너뛰고 결과 화면으로 스크롤하면 여전히 게임 없는 상태를 보게 되어 근본 해결이 아니다.

### D-19. 반응속도 게임을 선택 보너스에서 필수 마지막 단계로
- **선택**: 마지막 문항(12번째)에 답하면 결과가 아니라 곧장 `reaction-intro`로 넘어간다. `test-result`의 guard는
  `state.answers`가 다 찼어도 `state.lastReaction`이 없으면 `reaction-intro`로 되돌린다. 별도의 `reaction-result`
  화면은 없앴다 — 게임을 마치면 `finish()`가 바로 `test-result`로 보내고, 게임 통계는 그 결과 화면에 병합된다.
- **이유**: 사용자가 "12문항 결과"와 "게임 결과"를 서로 다른 두 결과로 인식했다 — 결과 화면이 게임 데이터를 이미
  점수에 반영하고 있었는데도(D-5), 화면이 둘로 나뉘어 있어 하나의 검사라는 게 안 드러났다. 게임을 문항과 같은
  줄에 놓고 결과를 하나로 합쳐야 "이 테스트의 결과"라는 게 명확해진다.
- **기각**: 결과 화면에 게임행 유도 카드만 남기고 흐름은 그대로 두기 — 여전히 게임을 건너뛸 수 있어 결과가
  설문만으로도, 설문+게임으로도 나올 수 있는 상태가 남는다. "필수"로 만들려면 guard로 강제해야 한다.
- **부수 효과**: `test-result` 재진입(뒤로가기 등) 시 게임을 안 거쳤으면 결과 대신 게임으로 보낸다 — 직접 URL
  접속·새로고침 후 재방문에도 동일하게 적용된다. `reaction-intro`/`reaction-play`도 문항 미완료면 `test-intro`로
  떨어진다(문항 없이 게임만 단독으로 열 수 없다).
- **검증**: `scripts/verify.cjs` — 문항 완료 직후 주소가 `/test/adhd/reaction`인지, 게임 없이 결과 주소로 들어가면
  `reaction-intro`로 떨어지는지, 최종 결과에 게임 분석 문구가 병합돼 있는지 확인한다.

### D-20. 반응속도 최고기록(`localStorage`) 게이미피케이션 제거
- **되돌림**: 반응속도 게임 인트로에 "내 최고기록" 칩을, 결과에 "🎉 새 최고기록!" 배지를 띄우고 `localStorage`에
  평균 반응시간의 개인 최고치를 저장하던 기능을 **전부 제거**했다.
- **이유**: 이 게임은 Go/No-Go 과제로 억제 실패·누락·반응시간 변산성을 측정하는 검사이지, 빨리 누르기 대회가
  아니다. "최고기록을 경신하라"는 프레이밍은 사용자가 정확도보다 속도를 우선하도록 유도하는데, 그러면 성급한
  반응(premature)·억제 실패(commission)가 늘어 충동성 점수를 오히려 왜곡시킨다. D-5에서 "빨리 누를수록
  충동적"이라는 채점 규칙 자체를 폐기한 것과 정확히 같은 이유로, 이번엔 채점이 아니라 **UI 프레이밍**에서
  같은 문제가 재발한 것이었다.
- **기각**: 배지 문구만 순화하고 유지 — 프레이밍이 남아 있는 한 "더 빨리"를 암시하는 효과는 그대로다. 근본
  원인(빠름을 성취로 표시하는 것)을 없애야 한다.
- **부수 효과**: `js/core/util.js`의 `bestReactionTime()`/`saveBestReactionTime()`이 미사용이 되어 함께 삭제했다.
  이제 이 앱은 영속 데이터가 전혀 없다(`CLAUDE.md` 식별자 참고).
- **재검토 조건**: 반응속도 자체를 성취로 다루는 기능을 다시 제안하지 말 것. 세션 내 참고용 숫자(이번 판
  평균 반응속도)를 보여주는 것과, 그것을 "기록"으로 저장·경신 알림하는 것은 다르다 — 전자는 유지하고 있다.
