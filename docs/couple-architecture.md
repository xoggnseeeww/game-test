# couple-architecture — 부부 관계 성향 체크

> 선택 로드 문서. `docs/architecture.md`가 15KB를 넘겨 테스트별 상세를 분리한 것 중 하나.
> 기획서(`AI 기반 부부 맞춤형 심리 진단 서비스 상세 설계본 v3.0`)의 §번호를 코드 주석에
> 그대로 달아뒀다 — 여기서 §5.3을 찾으면 `score.js`의 같은 §5.3 주석으로 이어진다.

## 0. 한 줄 요약

세 축(호칭·역할·자녀단계)을 고르면 그 상황에 맞는 문장으로 46문항이 조립되고, 채점 결과로
16유형 중 하나 + 네 성향의 연속 점수 + 확신도가 나온다. 배우자에게 링크를 보내 각자 답하면
두 결과를 합친 리포트(인지 격차·부모/연인 게이지·대화 스크립트)를 볼 수 있다.

## 1. 파일

```
js/tests/couple/
  data.js       46문항(가변 문항은 축별 3버전) · 16유형 · 리포트 문구 뱅크 · 슬러그 맵
  assemble.js   문항지 조립 — 셔플 · 요인 이격 · 역채점 분산 · QC 삽입 · 앵커 후미 고정 (DOM 모름)
  score.js      개인 채점 — 역채점 · 정규화 · 유효성 검사 · 유형/애착/갈등 판정 (DOM 모름)
  match.js      부부 매칭 — ΔDISC · Risk Matrix · Gap Score · 게이지 · 배우자 코드 코덱 (DOM 모름)
  screens.js    9개 화면 렌더 + 공유 카드 캔버스
  index.js      디스크립터: coupleTest(메타) + coupleScreens(화면 배열)
```

`assemble.js`가 `score.js`의 `REVERSE_CODES`를 가져다 쓴다(역채점 문항을 붙여놓지 않으려고).
순환 참조는 없다 — `assemble → score → data`, `assemble → data`.

## 2. 문항 구성 (기획서 §3.2·§4)

| 모듈 | 코드 | 문항 수 | 부부 간 비교 |
|------|------|---------|--------------|
| 행동성향 4요인 | D1–D4 · I1–I4 · S1–S4 · C1–C4 | 16 | ○ |
| 애착 2축 | A1–A4(불안) · V1–V4(회피) | 8 | ○ |
| 갈등 2축 | SC1–SC3(자기주장성) · OC1–OC3(관계배려성) | 6 | ○ |
| 앵커 | AN1–AN3 | 3 | ○ **Gap Score 전용** |
| 응답 품질 | QC1–QC2 | 2 | 비채점 |
| 가변 · 역할 | R1–R4(역할별 문장 다름) · R5–R6(문장 동일) | 6 | R1–R4 ✗ / R5–R6 ○ |
| 가변 · 자녀 | K1–K5 | 5 | ○ (부부가 같은 K축) |

역채점 9문항: `D4 I4 S4 C4 A4 V4 SC3 OC3 R6` (`score.js`의 `REVERSE_CODES`가 단일 소스).

**핵심 제약 — 문장이 다르면 빼지 않는다.** R1–R4는 역할마다 문장이 갈라지므로 두 사람의
점수를 빼도 그 차이를 "인지 격차"라고 부를 근거가 없다. 그래서 격차는 양쪽에 **완전히 같은
문장**으로 나가는 앵커 3문항에서만 뽑는다. `computeCouple()`이 돌려주는 `comparable`에
AN1–AN3 · R5 · R6 · K2 · K4만 담기는 이유이고, `test/couple.score.test.js`가 그 키 목록을
통째로 고정해두는 이유다.

## 3. 문항지 조립 (`assemble.js`)

```
셔플 → 요인 이격(최소 2) + 역채점 분산 → 역채점 붙은 쌍 보수 → QC 중반부 삽입 → 앵커 후미 고정
```

- **요인 이격**: 후보 중 **남은 문항이 가장 많은 요인부터** 놓는다. 앞에서부터 아무거나 고르면
  문항 수가 많은 요인(ROLE 6문항)이 뒤로 몰려 끝에서 규칙이 통째로 깨진다.
- **역채점 분산**: 같은 선택 루프에서 함께 본다. 이격을 맞춘 뒤에 역채점만 따로 스왑하면
  그 스왑이 방금 맞춘 이격을 다시 깨뜨린다. 그래도 남는 붙은 쌍은 `repairReverseRuns()`가
  이격을 깨지 않는 범위에서만 떼어놓는다.
- **앵커 후미 고정**: 앞 문항들에 답하며 자기 상황을 떠올린 뒤 답해야 회상 정확도가 오르고,
  이 구간 직전에 비공개 재고지를 한 번 더 띄울 수 있다(§6.5.2). 화면은 `anchorStartIndex()`로
  그 지점을 안다.

축 조합(6가지 역할×자녀)이 무엇이든 **문항 수와 코드 구성은 같다** — 체감 소요시간을 고정하고,
서로 다른 조합을 고른 두 사람도 요인 점수 기준으로는 같은 척도 위에 놓기 위해서다.

## 4. 채점 (`score.js`)

| 단계 | 내용 |
|------|------|
| 유효성 사전 검사(§5.0) | QC1≠2 · \|QC2−I1\|≥3 · 같은 값 80% 이상 · 소요시간 120초 미만 → 각 플래그 1 |
| 역채점 | `6 − 원응답값` |
| 정규화 | `(합 − 문항수) / (4 × 문항수) × 100` — 분모가 문항 수에서 파생된다 |
| 행동성향(§5.3) | 최댓값 요인 하나로 라벨. 1·2위 차이로 확신도 3단계. 동점은 D > C > S > I |
| 애착(§5.4) | 불안·회피 각각 50점 기준 2×2. 원점수 중앙값 ±1점은 "혼합"으로 표시 |
| 갈등(§5.5) | 두 축 좌표에서 5스타일. 절단점 40/60, 경계 근접이면 인접 스타일 언급 |

플래그 **2개 이상이면 결과를 내지 않는다**(재응답 유도). 1개면 결과 상단에 정확도 고지를
붙인다. 결합 리포트는 한쪽이라도 2개 이상이면 발급하지 않는다.

**정규화 칸 크기가 경계 판정의 기준이다.** 4문항 척도는 한 칸이 6.25점, 3문항 척도는 8.33점.
확신도·혼합 구간·경계 표시가 전부 이 칸 크기에서 파생되므로, 문항 수를 바꾸면 임계값을 따로
고칠 필요가 없다. (기획서 §5.5는 갈등 축 경계 폭도 6.25로 적어뒀지만 그 값은 4문항 척도의
칸이다 — 그대로 쓰면 원점수 1점 차이로 스타일이 뒤집히는 경우의 절반이 경계로 안 잡힌다.
`docs/decisions/2027-h1.md` D-33 참고.)

## 5. 부부 매칭 (`match.js`)

$$Match\_Score = 100 - (0.3 \cdot \Delta행동성향 + 1.0 \cdot Risk + 0.3 \cdot Gap)$$

- ΔDISC는 4차원 유클리드 거리를 2로 나눠 0~100으로 맞춘다(안 맞추면 가중치 0.3의 실제
  영향력이 설계 의도보다 커진다).
- Risk Matrix는 애착 조합 4×4 대칭 표. 집착형×거리두기형(추격자-도망자)이 최고값 18.
- Gap Score는 앵커 3문항의 100점 환산 차이 평균. **부호를 살린 방향값도 함께** 돌려준다.

**점수는 사용자에게 숫자로 나가지 않는다.** 가중치와 Risk Matrix가 실증값이 아니라 이론적
배정값이라, "62점"이라는 숫자가 근거 없는 낙인이 될 수 있다. 화면에는 구간 서술과 **구성
요소 3개**(성향 차이 / 애착 조합 / 인지 격차)만 나간다. 구간 경계 ±3점은 오차 범위 안이므로
더 완만한(높은) 쪽 문구를 쓴다.

부모·연인 게이지는 K2(단둘 시간, 가산)와 K4(양육 스트레스의 관계 침식, 감산)에서 나온다.
**자녀 단계를 서로 다르게 고르면 게이지를 계산하지 않고 이유를 말한다** — 단계가 다르면 두
사람이 받은 문장 자체가 달라 평균을 낼 근거가 없다.

## 6. 배우자 코드 (백엔드 없음)

기획서 §10의 페어링 코드(서버 발급·72시간 만료·1회 매칭)는 백엔드를 전제한다. 이 사이트에는
백엔드가 없으므로, 결합 계산에 필요한 값만 담은 21자 코드를 주소에 실어 보낸다.

```
/test/couple/pair?p=1001ggbcga5d31414151c
 └ 버전(1) + 필드 20자(base36) + 체크섬(1)
```

담기는 값은 `PAYLOAD_FIELDS`가 전부다: 세 축 · 요인 원점수 8개 · 비교 가능 문항 7개
(AN1–AN3 · R5 · R6 · K2 · K4) · 플래그 수. **46문항 응답을 통째로 싣지 않는다.**

> ⚠️ **필드 순서가 곧 코드의 자리다.** 순서를 바꾸거나 항목을 끼워넣으면 이미 공유된 링크가
> 조용히 다른 값으로 해석된다 — 늘리려면 `VERSION`을 올리고 분기해야 한다.

> ⚠️ **이 코드는 암호화가 아니다.** 앵커·K2·K4·R5·R6은 개별 문항 응답값이고, 격차와 게이지가
> 문항 단위 차이에서 나오므로 뺄 수 없다. 화면에서는 배우자의 문항별 응답을 어디에도
> 표시하지 않지만, 기획서 §6.5.1의 "영구 비공개"를 기술적으로 보장하지는 못한다. 그래서
> 사전 고지 문구도 "배우자가 볼 수 없습니다"가 아니라 **"어느 화면에도 표시되지 않습니다"**로
> 적었다(`docs/decisions/2027-h1.md` D-34).

깨진 코드(카카오톡에서 링크 끝이 잘려 붙는 경우가 실제로 있다)는 체크섬에서 걸러져
인트로로 떨어진다.

## 7. 화면 흐름

```
couple-intro ─→ couple-setup ─→ couple-question(46) ─→ couple-ad ─┬→ couple-result
   /test/couple   /setup           /play                  /ad      │     /result
                                                                   └→ couple-report  (배우자 코드가 있을 때)
                                                                         /together
couple-result ─→ couple-invite ─(링크)→ 배우자 기기의 couple-pair ─→ couple-setup ...
                    /invite                    /pair?p=<코드>
```

- `couple-pair`의 guard는 코드를 한 번 풀어 `state.couple.partner`에 캐시한다. 이미 본인 응답이
  끝나 있으면 곧장 `couple-report`로 보낸다.
- **초대받은 쪽은 문항을 마치면 개인 결과가 아니라 결합 결과로 간다.** 초대 링크의 목적이
  "합쳐 보기"인데 개인 결과에서 멈추면 스스로 다시 찾아가야 한다 — `couple-ad`의 continue가
  `state.couple.partner` 유무로 목적지를 고른다.
- `couple-shared`(`/test/couple/result/<슬러그>`)는 16유형 소개 페이지. 공유 버튼은 **이 주소만**
  내보낸다 — 배우자 코드가 담긴 주소를 공유 버튼에 걸면 아무에게나 내 점수가 실린 링크가 나간다.

## 8. 결과 전달 안전 장치 (기획서 §6.5·§9)

| 장치 | 어디에 |
|------|--------|
| 응답 공개 범위 사전 고지 | 인트로 · 초대받은 화면(`.cp-privacy`) |
| 앵커 구간 재고지 | 문항 화면, 앵커 진입 시(`#cp-anchor-notice`) |
| 유형 라벨 단독 노출 금지 | 결과에 항상 4요인 + 애착 2축 점수 + 확신도 동반 |
| 백분위·석차 표현 금지 | 규준 표본이 없으므로 절대값과 기준선만 (§6.2) |
| 점수 숫자 노출 금지 | 결합 결과는 구간 서술 + 구성 요소만 (§7.4) |
| 지목 금지 | "누가 낮게 답했다"가 아니라 "두 분이 느끼는 정도에 차이가 있다" (§6.5.3) |
| 격차엔 항상 해법 동반 | 격차 블록에 대화 스크립트가 붙는다 (§8.4) |
| 상시 안내 링크 | 결과·결합 결과 하단에 감지·분기 없이 항상 (§9.2) |
| 서비스 성격 고지 | 인트로 · 결과 · 결합 결과 (§9.3) |

안내 전화번호는 기획서에 적힌 것을 그대로 쓰지 않았다 — 1577-1366은 건강가정지원센터가 아니라
**다누리콜센터**(다문화가족)이고, 1393은 2024년부터 **109로 통합**돼 안내 번호로 부적절하다.
가족센터 가족상담 `1577-9337` · 정신건강 상담전화 `1577-0199`로 바꿔 넣었다.

## 9. 기획서에서 구현하지 않은 것

백엔드·계정·수집 데이터가 없어서 **원리적으로 못 하는** 항목들이다. 서버가 생기기 전에는
되살릴 수 없다.

| 기획서 | 왜 못 하나 |
|--------|-----------|
| §5.2 2차 표준화(백분위) · §5.7 세그먼트 비교 · §6.2 석차 | 규준 표본(n≥300)을 모을 저장소가 없다. 기획서도 표본 확보 전에는 쓰지 말라고 했으므로 **금지 상태 그대로**가 맞다 |
| §10 페어링 코드 만료·1회 매칭 · 재검사 30일 쿨다운 · 데이터 보관/파기 | 서버 상태가 없다. 링크는 만료되지 않는다 |
| §10 Cronbach's α 모니터링 · 응답 품질 주간 통계 | 응답을 수집하지 않는다 |
| §11 파일럿(W7) 기반 문항 정제·절단점 재조정 | 데이터 수집 경로 자체가 없다 |

즉 **§5.0의 응답 품질 검사는 개인 세션 안에서만 동작**하고, 그 결과가 축적되지는 않는다.
